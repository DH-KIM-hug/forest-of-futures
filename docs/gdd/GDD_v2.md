## 2. 핵심 루프와 진행 단계

### 2.1 분 단위 (한 번 접속 5~10분, 정산 3분)
```
[줍는다/캔다] ─▶ 현금 · 지갑(코인) ─▶ [갚는다] 원금 탕감 도장 (이자가 준다, 확실)
     ▲                              ├▶ [번다]   채굴 설비 (자동으로 캔다, 전기세)
     │                              └▶ [건다]   선물 판돈 (크게 불거나 사라진다)
     └──── 3분마다 정산: 캔 값 − 전기세 − 이자 − 생활비 ────┘
            못 내면 → 급매 → 연체 → 가압류 딱지 → 압류 → 파산
```
1. 일터를 누른다. 0단계는 도토리가 현금으로, 1단계부터는 코인이 지갑에 쌓인다. 지갑의 값은 실제 시세대로 오르내린다("지금 팔까, 버틸까").
2. HUD에 다음 정산 수지가 항상 보인다: `캔 값 +5,700 / 전기세 −3,990 / 이자·생활비 −10,000`. 합이 0 이상이 되는 순간이 **흑자 전환**이다.
3. 남는 돈을 도장·설비·판돈 가운데 어디에 둘지 고른다.
4. 속보 띠(사실만)와 마을 말풍선(NPC의 권유)이 흐른다. 따를지 말지 고른다.
5. 정산에서 못 내면 딱지가 붙고, 더 못 내면 지갑과 쳇바퀴가 실려 간다. 가져갈 것이 없으면 파산.

### 2.2 접속과 접속 사이
| 무엇이 | 자리를 비운 동안 | 상태 |
|---|---|---|
| 선물 포지션 | **전 구간 계속 돈다.** 청산·손절·익절·펀딩비가 서버 기록의 그 시각 가격으로 처리된다 | [사용자 확정] |
| 경제(설비 채굴·전기세·이자·생활비·연체) | 나간 뒤 **정산 2회(6분)까지만** 돌고 멈춘다(가문 특성 `idle`로 6회까지). 접속하면 몫이 다시 찬다 | [사용자 확정: 제한 / 제안: 2회] |
| 0단계(쳇바퀴 없음)의 경제 | **돌지 않는다(0회)**. 방치할 설비가 없으면 방치 정산도 없다 | [제안][시뮬 필요] |
| 연체 보호 | 어느 곳이든 연체가 한도 − 1에 닿으면 그 전에 멈춘다. 자는 사이 연체로는 파산하지 않는다 | [제안, v1 유지] |
| 청산으로 빈손 | 설비도 지갑도 없고 빚이 있으면 돌아왔을 때 시간표 → 엔딩 | [사용자 확정 방향] |

하루 5번 접속이면 경제는 하루 정산 22회쯤 돈다. 한 세대는 실제 **1~3일**이다.

### 2.3 세대
```
세대 시작(상속 방식) → 줍기 → 채굴 → 거래 → 끝
  끝 ① 파산: 엔딩 카드(마지막 세 장면 · 한 끗 차이 · 다음 세대에 남는 것) → 재산 명세서 → 상속포기(완전 환생) / 한정승인(반쪽 환생) / 단순승인(이어 하기)
  끝 ② 빚 없는 은퇴: 엔딩 없음 → 증여(자산·현금 그대로 + 세금 빚) → 다음 세대
가문에 남는 것: 한(恨)과 가문 특성 트리 · 장부(엔딩) · 최고 재산 · 정보 수첩 · 유품함 · 기질 · 채권처의 원한/연줄 · 마을의 흔적
```

### 2.4 진행 단계 — 단계별 열림 [사용자 확정 2026-11-25: 순서 / 제안: 조건·숫자]

| 단계 | 이름 | 여는 조건 | 클리커가 주는 것 | 열리는 것 | 목표 시점(2세대 첫 플레이) |
|---|---|---|---|---|---|
| 0 | 도토리 줍기 | 시작 | 1회 **현금 27** (안전, 시세와 무관) | 대출·도장·친구·이사·기록관·전광판 | 시작 |
| 1 | 쳇바퀴 채굴 | 줍기 누적 200회 → 일터에 '쳇바퀴 팝니다' 팻말 → **도토코인 쳇바퀴 10,000** 구매 | 1회 코인 `(27 + 0.54 × 설비 초당 순수입) × 탭 배수 ÷ 세대 시작가` | 지갑, 팔기, 채굴 설비 사다리, 업그레이드, 거래 탭의 차트(읽기 전용) | **첫 접속 안(3~6분)** |
| 1-a | 종목 쳇바퀴 해금 | 밤더리움: 누적 채굴 2만어치 / 멍도토: 누적 채굴 5만어치 / 삼솔전자: 오두막 이상 | 올라탄 쳇바퀴의 종목 | 종목별 전용 쳇바퀴(3.3) | 밤더리움 첫날, 멍도토 첫날 후반, 삼솔전자 2~3일차 |
| 2 | 선물 거래 | 이번 세대 누적 채굴 **5만 도토리어치** → 캐피탈 창구 '선물 계좌 개설'(사전교육 3장 + 모의거래 1회 + 예탁금 확인 3만) | 같음 | 거래 탭 주문. 배율 상한 10배 → 50배 → 200배 | **첫날, 2~4번째 접속** |
| 3 | 옵션 (2단계, MVP 아님) | 11장 | | | |

- **0단계에서 살아남기** [제안][시뮬 필요]: 시작 정산 지출은 10,000(이자 9,000 + 생활비 1,000). 초당 1.5회 줍기는 정산당 7,290이라 접속 중에도 정산마다 2,710씩 준다. 대신 0단계는 오프라인 정산이 없어서 현금 10만으로 **접속 정산 36회(실제 플레이 약 1시간 50분)** 를 버틴다. 첫 쳇바퀴는 200회(약 2분 15초) 뒤에 열리므로 성실히 하면 첫 쳇바퀴 전에 망하지 않는다. "노동만으로는 빚을 못 갚는다"는 원칙은 유지된다(SIM_v2의 '쳇바퀴만 7.8시간 파산'은 오프라인 정산 2회가 돌던 값이다). 줍기 값을 40으로 올려 접속 중 수지를 +800으로 만드는 안은 13장 T-2.
- **첫 쳇바퀴 이후의 숫자는 SIM_v2 개정 6에서 출발한다**: 도토코인 쳇바퀴는 자동 수입이 0이고 전기세도 0이다(손으로 돌린다). 그 위의 설비 7단계를 도토코인에 붙였을 때의 값은 시뮬레이션한 값 그대로다. 첫 쳇바퀴 값 10,000만큼만 출발이 늦다. 종목별 배수(3.3)와 업그레이드(3.4a)는 그 뒤에 얹은 [제안]이라 다시 시뮬레이션해야 한다.
- **왜 채굴이 줍기보다 나은가**: 1회 값은 같고(27어치), 설비를 사면 1회 값과 자동 수입이 함께 는다. 대신 시세에 묶인다. '캐는 즉시 팔기'를 켜면 수수료 0.5%를 내고 줍기처럼 안전해진다.
- **선물 개방 = 현실 제도의 패러디** [제안]: 한국의 개인 파생상품 계좌(사전교육 + 모의거래 + 기본예탁금)를 그대로 빌린다. 족제비 대표가 교육을 3장으로 끝내 주고, 모의거래는 한 번 눌러 보면 통과다. 예탁금 3만은 **확인만 하고 떼지 않는다**(현금 + 지갑 평가액 ≥ 30,000). 개설 직후 족제비는 "첫 3회 이자 반값" 대출을 권한다(3.5) — 계좌를 열어 준 이유다.
- **배율 상한도 단계적으로** [제안][시뮬 필요]: 개설 직후 **10배** → 끝난 거래 3건(정리·손절·익절·청산 모두 셈) 뒤 **50배** → 끝난 거래 10건 + 캐피탈 창구에서 '고위험 거래 확인서'에 도장 → **200배**.
  - 현실감: 실제 거래소도 새 계정의 배율을 제한하고, 확인서 한 장으로 풀어 준다. 서류 한 장이 200배를 여는 것이 이 게임의 농담이다.
  - 초반 파산률: 상한이 없으면 2세대가 첫 접속에 전액 200배로 33분 안에 100% 파산했다(SIM_v2 '200배 한 방'). 10배는 하루를 걸어 둬도 거의 청산되지 않으므로(25배의 24시간 청산이 24.8%) 첫날은 "거래를 배우는 날"이 된다.
  - 엔딩 분포: 200배가 조건인 청산·낚임 엔딩(END-111·151·153·156·165·166·175·192·193·194·196 등)은 2일차 이후나 계좌를 물려받은 세대에서 나온다. 계좌를 연 직후에는 END-160(10배 이하 청산)이 가장 가깝다. "계좌를 열자마자 청산"을 가르는 조건 키 `acctAgeSettles`를 통계에 넣어 둔다(배정은 13장 T-9).
  - 대안: 상한 없이 200배를 바로 여는 안(엔딩이 빨리 나오고 첫 판이 30분에 끝날 수 있다). 13장 T-3.
- **대물림과 단계** [제안]: 단계는 가진 것에서 나온다 — 쳇바퀴가 있으면 1단계, 선물 계좌가 있으면 2단계.

| 시작 방식 | 쳇바퀴·설비 | 선물 계좌·배율 상한 | 시작 단계 |
|---|---|---|---|
| 2세대(첫 플레이) | 없음 | 없음 | 0 |
| 단순승인(이어 하기) | 부모의 남은 종목 쳇바퀴·설비·업그레이드 + 가업 간판 1대 | **물려받는다**(부모가 연 상한 그대로) | 1 또는 2 |
| 증여(은퇴) | 전부 그대로 | 물려받는다 | 2 |

## 3. 시스템 규칙

### 3.1 시간과 정산
- 틱 1초. 서버 틱 번호가 시계다. **정산 주기 180틱(3분)** [사용자 확정]. 정산 타이머는 앱이 켜져 있는 동안 어느 탭에서든 흐른다.
- **하루 = 정산 4회**: 아침 · 낮 · 저녁 · 밤(`time = settleNo mod 4`). 밤에는 조합과 세무서가 닫힌다(대출·도장 불가, 사건 기록 `closed:bank`). 시장은 닫히지 않는다. 기기 시각은 규칙에 쓰지 않는다.
- **정산 순서**(한 틱 안에서 차례대로)
  1. **채굴**: 켜져 있는 설비와 '관성 바퀴'마다 `캐는 값 ÷ 그 종목의 세대 시작가` 개의 코인을 그 종목 지갑에 캔다. 가압류 중이면 30%는 지갑에 오지 않고 시가로 그 채권처 원금에서 깎인다.
  2. **전기세**: 종목별로 켜져 있는 설비의 전기세 합(도토리)을 **그 종목 지갑의 코인에서 시가로** 뗀다(수수료 없음. 모자라면 평가액 큰 다른 종목 순). 모자란 만큼은 4의 청구액에 더한다.
  3. **펀딩비**: 열린 포지션마다 명목의 0.001%를 증거금에서 뺀다. 뺀 뒤 `증거금 + 손익 ≤ 명목 × 0.1%`이면 청산.
  4. **청구액**: 이자(채권처별 `round(원금 × 이자율 × 금리 사건 배수)`) + 생활비(집 단계) + 전기세 잔여 + 기한이 된 세금.
  5. **급매**: 현금 < 청구액이고 지갑에 잠기지 않은 코인이 있으면 모자란 금액 ÷ 0.97어치(올림)를 자동으로 판다(수수료 3%).
  6. **납부**: `독사 → 오소리 → 캐피탈 → 조합 → 세무서 → 생활비·전기세` 순서. 모자라면 낼 수 있는 만큼만.
  7. **연체 처리**: 미납 이자는 원금에 더하고 그곳의 연체 +1, 다 낸 곳은 0. 텐트의 생활비·전기세 미납은 연체가 아니라 캐피탈 원금으로 넘어간다(비상금 대출, 한도와 무관). 집(오두막 이상)은 미납분이 쌓이고 3회 연속이면 파산 사유. 이어서 3.6의 딱지·압류.
  8. **친구**: 갚기로 한 날이 지난 빚 → 신뢰 −20. 연락처 추심 → 전원 −30. 신뢰 0 이하 → 절교.
  9. **게임 안 사건**: 남은 회차 −1, 새 사건 추첨(3.12). **채권처의 제안** 추첨(3.5).
  10. **파산 검사**(3.6) → 원인 판정(3.15). 파산이면 여기서 끝.
  11. 통계·사건 기록·최고 순자산 갱신, 하루 시각 넘김, 저장, 정산 한 줄을 속보 띠에.
- **순자산** = 현금 + 지갑 평가액 + 포지션 평가액 + 설비 평가액(구매가의 80%) + 집 평가액 × 0.9 − 총부채.

### 3.2 도토리 줍기 (0단계)
- 일터 무대를 누를 때마다 현금 +27(기질·가압류 반영). 초당 12회까지만 인정. 업그레이드·기질로 생긴 소수는 버리지 않고 쌓아 두었다가 1이 넘을 때 현금에 더한다.
- 줍기 누적 200회가 되면 일터에 '쳇바퀴 팝니다' 팻말이 서고 [도토코인 쳇바퀴 10,000] 버튼이 생긴다. 줍기 업그레이드 `glove`는 처음부터 살 수 있다(3.4a). 현금이 모자라면 꺼져 있고 "현금 부족"이 보인다.
- 2세대 첫 플레이에서 팻말이 설 때 칩멍크 말풍선이 한 번 뜨고 버튼이 한 번 반짝인다(앞 설계의 '자루 안내'를 대신한다) [사용자 확정: 초반 난도 유지 + 길만 알려 준다].

### 3.3 쳇바퀴 채굴과 지갑 (1단계부터) [사용자 확정: 구조 · 종목별 쳇바퀴 / 제안: 숫자]
**쳇바퀴는 종목별로 산다** [사용자 확정 2026-11-25 — 앞 설계의 "쳇바퀴 전체가 한 종목을 캐고 언제든 바꾼다"를 대체]. 종목마다 전용 쳇바퀴가 있고, 그 쳇바퀴와 거기 붙인 설비는 그 종목만 캔다.

| 종목 쳇바퀴 | id | 가격 | 여는 조건(레벨링) [제안] | 캐는 배수 `g` | 전기 배수 `p` | 기준가 순수입 `g − p` | 역마진이 되는 하락 폭 | 탭 배수 | 간판·색 |
|---|---|---|---|---|---|---|---|---|---|
| 도토코인 쳇바퀴 | `wheel:DTC` | 10,000 | 줍기 누적 200회 (1단계의 문) | 1.00 | 0.70 | 0.30 | −30% | 1.00 | 도토리 갈색 |
| 밤더리움 쳇바퀴 | `wheel:BTH` | 30,000 | 이번 세대 누적 채굴 2만어치 | 1.10 | 0.78 | 0.32 | −29% | 1.07 | 밤 보라 |
| 멍도토 쳇바퀴 | `wheel:MDT` | 15,000 | 누적 채굴 5만어치(선물 계좌 조건과 같은 때). 여우 선배 말풍선 "요즘 다들 멍도토 캔다" | 1.30 | 0.95 | 0.35 | −27% | 1.17 | 노랑, 발바닥 간판 |
| 삼솔전자 쳇바퀴 | `wheel:SMS` | 60,000 | 오두막 이상(주소지가 있어야 협력 채굴 계약) | 1.20 | 0.86 | 0.34 | −28% | 1.13 | 파랑, 반듯한 간판 |

- 읽는 법 [제안][시뮬 필요]: 거친 종목일수록 **싸게 열리고 많이 캐지만**(g가 크다) 전기도 많이 먹어서(p가 크다) 값이 조금만 내려도 역마진이 된다. 기준가에서는 멍도토가 도토코인보다 17% 더 벌고, 값이 10% 내리면 도토코인은 순수입 −33%, 멍도토는 −37%다. 종목 쳇바퀴는 종목마다 1대, 자동 수입은 0이다(업그레이드 '관성 바퀴'로 조금 생긴다, 3.4a).
- **포트폴리오**: 설비를 여러 종목 쳇바퀴에 나눠 붙이면 한 종목의 폭락에 덜 흔들리고, 한 종목에 몰면 그 종목이 오를 때 가장 많이 번다. 일터 패널에 `캐는 값 비중: 도토코인 60% · 멍도토 40%`가 보인다(사실만).

| 항목 | 규칙 |
|---|---|
| 탭 | 칩멍크는 한 번에 한 쳇바퀴에 올라탄다(무대에서 쳇바퀴를 눌러 옮겨 탄다). 1회 채굴량 = `(27 + 0.54 × 켜진 설비 전체의 기준 초당 순수입 합) × 탭 배수 × 업그레이드 ÷ 그 종목의 세대 시작가` 개 |
| 세대 시작가 | 그 세대가 시작한 틱의 서버 가격(종목별). 세대 동안 고정. 쳇바퀴를 세대 중간에 사도 같은 값을 쓴다 |
| 지갑 | 종목별 수량. 평가액 = 수량 × 지금 가격. HUD에 `지갑 12,400 (▼3.1%)`(도토리 환산 합계, 가진 코인의 세대 시작가 대비 가중 등락) |
| 팔기 | 일터 패널에서 종목별 [전부] [절반]. 수수료 0.5%(업그레이드로 0.2%까지). 받는 돈 = `floor(평가액 × (1 − 수수료))` |
| 캐는 즉시 팔기 | 종목 쳇바퀴마다 스위치. 켜면 그 종목은 탭과 설비가 캔 것이 지갑에 쌓이지 않고 곧장 현금이 된다(전기세는 그 현금에서 낸다) |
| 급매 | 정산 5단계. 수수료 3%. 평가액이 큰 종목부터 판다. 누적액은 통계 `forcedSold` |
| 담보 | 지갑 평가액(잠기지 않은 것)의 50%가 캐피탈 한도에 더해진다. 값이 내리면 한도도 내린다(회수는 없고 추가 대출만 막힌다) |
| 숏 보험 | 가진 종목의 숏을 그 종목 지갑 평가액만큼 걸어 두면 폭락 때 지갑이 준 만큼 숏이 번다. 거래 탭에 `지갑 도토코인 12,400어치 — 숏으로 지킨 비율 0%`(사실만) |
| 사는 기능 | **없다.** 코인은 캐서만 얻는다(현물 매수는 2단계 옵션의 배정으로만) [제안] |

### 3.4 채굴 설비 사다리 (방치 자산) [사용자 확정: 방향 / 제안: 숫자 — `balance_v2.draft.json` `assets`]
**사다리는 공용이고, 한 대 한 대를 종목 쳇바퀴에 붙인다** [제안]. 가격표와 대수 한도(단계마다 3대)는 종목과 무관하게 하나다. 살 때 가진 종목 쳇바퀴 가운데 하나를 고르고, 그 설비는 그 종목만 캔다. 옮겨 붙이려면 구매가의 5%를 낸다. 이렇게 하면 전체 생산량은 시뮬레이션한 값(공용 21대)과 같고, 종목 사이의 배분만 플레이어의 선택이 된다.

| 단계 | id | 설비 | 가격(첫 대) | 정산당 캐는 값(기준) | 전기세(기준, 정산당) | 순수입(기준) | 초당 순수입 | 여는 조건 |
|---|---|---|---|---|---|---|---|---|
| 1 | `wheel2` | 보조 쳇바퀴 | 20,000 | 5,700 | 3,990 | 1,710 | 9.5 | 종목 쳇바퀴 1대 이상 |
| 2 | `helper` | 알바 햄스터 | 60,000 | 14,700 | 10,290 | 4,410 | 24.5 | 〃 |
| 3 | `row` | 쳇바퀴 줄(다섯 대) | 150,000 | 32,250 | 22,575 | 9,675 | 53.75 | 〃 |
| 4 | `generator` | 소형 발전기 | 400,000 | 75,000 | 52,500 | 22,500 | 125 | 〃 |
| 5 | `shed` | 채굴 헛간 | 1,500,000 | 240,000 | 168,000 | 72,000 | 400 | 오두막 이상. 조합 담보 가능 |
| 6 | `powerroom` | 지하 발전실 | 8,000,000 | 1,020,000 | 714,000 | 306,000 | 1,700 | 창고 이상. 조합 담보 가능 |
| 7 | `farm` | 채굴 공장 | 40,000,000 | 3,900,000 | 2,730,000 | 1,170,000 | 6,500 | 별장 이상. 조합 담보 가능 |

- 표는 도토코인 쳇바퀴에 붙였을 때의 값이다. 종목 `c`에 붙이면 **캐는 값 = 표 × g(c) ÷ 1.00, 전기세 = 표의 캐는 값 × p(c)**. 예: 보조 쳇바퀴를 멍도토에 붙이면 캐는 값 7,410, 전기세 5,415, 기준가 순수입 1,995.
- 단계마다 3대까지(전 종목 합), 둘째·셋째는 1.25배씩 비싸다(20,000 → 25,000 → 31,250).
- 지금 순수입 = `캐는 값 × (그 종목의 지금 가격 ÷ 세대 시작가) − 전기세`. 0 이하면 그 쳇바퀴와 설비에 붉은 **'역마진' 딱지**. 설비마다, 그리고 종목 쳇바퀴마다 [끄기] 스위치(끄면 채굴 0, 전기세 0).
- 전기세는 **그 종목의 코인에서 시가로** 먼저 뗀다. 모자라면 다른 종목(평가액 큰 순), 그래도 모자라면 현금 청구.
- 값: 평가액 = 구매가 × 80%(순자산·담보·세금) / 팔기 = 구매가 × 60%(딱지 붙은 것은 못 판다, 시도하면 사건 기록 `sell_blocked`) / 압류·공매 = 구매가 × 50%. 종목 쳇바퀴도 같다. 업그레이드에 쓴 돈은 어느 값에도 들어가지 않는다.
- 담보: 설비·종목 쳇바퀴 평가액의 50% → 캐피탈 한도. 헛간 이상 평가액의 60% → 조합 한도.
- 6단계 지하 발전실은 END-054의 발전실과 같은 방이다(시작도 쳇바퀴, 끝도 쳇바퀴).
- 통계: `assetsEver`·`assetsOwned`는 설비 1~7단계만 센다(종목 쳇바퀴는 세지 않는다) [제안]. `laborTaps`는 줍기와 채굴 탭의 합. `mineConcentration` = 켜진 설비의 캐는 값 가운데 가장 큰 종목의 비중(%), `mineTopCoin` = 그 종목.

### 3.4a 업그레이드 — 잘게 쪼갠 효율 [사용자 확정 2026-11-25: "클리커답게 효율 미세하게 업그레이드" / 제안: 목록·숫자][시뮬 필요]
- 한 단계는 작은 개선(+2~5%)이고, 값은 `비용(단계 n → n+1) = 기준값 × r^n`(올림)으로 오른다. 같은 줄 안에서는 더하고(+3% × 5단계 = +15%), 다른 줄끼리는 곱한다.
- **기준**: 어느 업그레이드든 한 단계의 정산당 수익률은 같은 돈으로 살 수 있는 설비의 절반 이하로 둔다. 설비가 주된 성장이고 업그레이드는 남는 잔돈의 쓸 곳이다. 그래서 2.4의 목표 시점(첫 쳇바퀴 3~6분, 선물 계좌 첫날)을 당기지 않는다 — 시뮬레이션으로 확인할 항목.
- **보여야 한다**(메모: 클리커는 캐릭터의 몸·소품으로): 줄마다 칩멍크나 쳇바퀴의 생김새가 단계 묶음(1 / 5 / 10 / 최고)마다 바뀐다.

| 줄 id | 이름(현실 패러디) | 붙는 곳 | 한 단계 효과 | 최고 단계 | 기준값 | r | 보이는 것 |
|---|---|---|---|---|---|---|---|
| `glove` | 목장갑 → 코팅 장갑 → "산재 처리 안 되는 장갑" | 칩멍크(줍기) | 줍기 1회 +4% | 10 | 4,000 | 1.15 | 장갑이 생기고 색이 바뀐다 |
| `shoes` | 시장표 운동화 → 러닝화 → 한정판 | 칩멍크(채굴 탭) | 채굴 1회 +3% | 15 | 5,000 | 1.12 | 운동화. 달릴 때 먼지 |
| `oil` | 기름칠 → 베어링 교체 → 무소음 베어링 | 종목 쳇바퀴별 | 그 종목에 붙은 설비의 캐는 값 +2% | 20 | 그 쳇바퀴 가격 × 20% | 1.10 | 쳇바퀴 축이 반짝인다. 삐걱 소리가 사라진다 |
| `spokes` | 바퀴 살 교체 → 관성 바퀴 → "영구 기관(아님)" | 종목 쳇바퀴별 | 그 쳇바퀴가 혼자 도는 양: 정산당 기준 150어치 × g (전기세 없음) | 10 | 3,000 | 1.15 | 살이 굵어지고 바퀴가 커진다. 손을 떼도 천천히 돈다 |
| `power` | 절전 멀티탭 → 심야 전기 요금제 → 한전 직원 지인 | 종목 쳇바퀴별 | 그 종목의 전기세 −1% | 15 | 그 쳇바퀴 가격 × 30% | 1.12 | 쳇바퀴 옆 전선·계량기 |
| `tier:<설비 id>` | 알바 교육 / 줄 맞추기 / 발전기 정비 / 헛간 환기 / 발전실 배선 / 공장 3교대 | 설비 단계별(전 종목) | 그 단계 설비의 캐는 값 +2% | 10 | 그 설비 첫 대 가격 × 5% | 1.12 | 알바 햄스터의 작업모, 발전기 연기 색 등 |
| `fee` | 단골 환전상 → 우수 고객 → "VIP(수수료는 받습니다)" | 가문이 아니라 그 세대 | 팔기 수수료 −0.03%p (0.5% → 0.2%) | 10 | 5,000 | 1.15 | 지갑 주머니에 단골 도장 |

- 급매 수수료(3%)와 선물 수수료는 업그레이드로 줄지 않는다.
- **압류와 업그레이드**: 업그레이드는 붙은 것과 운명을 같이한다. 종목 쳇바퀴가 실려 가면 그 쳇바퀴의 `oil`·`spokes`·`power`가 0이 된다. 어떤 설비 단계가 0대가 되면 그 `tier:*`가 0이 된다. 몸에 걸친 것(`glove`·`shoes`)과 `fee`는 압류되지 않는다. 압류로 빚에서 깎이는 값은 구매가 기준이라 업그레이드 값은 쳐주지 않는다(속보 띠: "기름칠 값은 평가에 포함되지 않습니다.").
- **대물림과 업그레이드**: 단순승인·증여 — 물려받은 쳇바퀴·설비에 붙은 업그레이드는 그대로, `glove`·`shoes`는 절반(내림)만("물려 신는다"), `fee`는 0. 한정승인·상속포기 — 전부 0.
- **표기**: 업그레이드 목록·건물 이름표처럼 좁은 곳은 큰 수를 줄여 쓴다(`9,500` / `1.2만` / `3,400만` / `1.5억`, 유효 숫자 2~3자리, 내림). HUD·창구·정산 줄은 전체 숫자.

- **원금 탕감 도장** [사용자 확정: 채권처별]: 현금 −도장액, 원금 −도장액. 배수 칩 `×1 / ×10 / 전액`. 원금 0이면 '완납' 도장(큰 연출은 완납·강제 청산·파산 세 번뿐).
- **꼬리표**: 빌리고 60초 안에 선물에 진입하면 포지션에 `fundedBy`(빌린 곳). 빌리고 60초 안에 다른 곳에 도장을 찍으면 돌려막기(`refi.*`).
- **채권처의 제안** [제안]: 정산 뒤 20% 확률로 하나가 창구 말풍선으로 온다(같은 제안은 정산 5회에 한 번).

### 3.6 연체 → 가압류 → 압류 → 파산 [제안]
| 단계 | 조건 | 일어나는 일 | 보이는 것 |
|---|---|---|---|
| 1 독촉 | 어느 곳이든 연체 1회 | 그 채권처가 설비 1대에 **가압류 딱지**(오소리: 싼 것부터 / 캐피탈·독사·세무서: 비싼 것부터 / 조합: 헛간 이상만. 같은 단계가 여러 종목에 있으면 **지금 순수입이 큰 종목의 것부터** — 잘 도는 것부터 가져간다. 설비가 없으면 종목 쳇바퀴에, 그것도 없으면 지갑에). 딱지가 있는 동안 줍기·채굴 수입의 30%가 그 채권처 원금에서 깎인다. 딱지 붙은 설비는 못 판다 | 쳇바퀴 위의 딱지(채권처 색), HUD "수입 30% 가압류 중" |
| 2 압류 | 연체가 한도에 닿음 | **지갑이 먼저**: 평가액 1,000 이상이면 지갑 전부가 넘어가고 시가의 90%가 원금에서 깎인다. 지갑이 비었으면 딱지 붙은 설비 1대(구매가의 50%). 설비가 다 떠난 종목 쳇바퀴는 그다음 차례다(싼 쳇바퀴부터, 설비가 붙어 있는 쳇바퀴는 설비보다 먼저 가져가지 않는다). 쳇바퀴가 실려 가면 그 종목의 업그레이드도 사라진다. 연체는 한도 − 1에 머문다(다음 정산에 또 못 내면 또 하나) | 압류 수레가 쳇바퀴째 실어 간다 |
| 3 파산 | 한도에 닿았는데 가져갈 지갑도 설비도 종목 쳇바퀴도 없음 | 집이 있으면 경매(70%)에 넘어가고 엔딩 | 붉은 '파산' 도장 |

- **청산 즉시 파산**: 강제 청산 직후 `현금 + 지갑 평가액 + 다른 포지션 평가액 < 1,000`이고 설비·종목 쳇바퀴가 0대이고 총부채 > 0이면 그 자리에서 파산. 설비가 하나라도 있으면 아니다. 빚이 0이면 파산은 없다.
- **관계 파산**: 절교 3명이면 다음 정산에 파산.
- **유지비 파산**: 오두막 이상에서 생활비·전기세 미납 3회 연속.

### 3.10 선물 거래 (2단계부터)
- 종목마다 포지션 1개(최대 5개). 격리 마진(잃는 돈은 그 포지션의 증거금까지).
- 입력(한 화면, 팝업·스크롤 없음 [사용자 확정]): 방향 롱/숏 · 배율 `1·2·5·10·25·50·100·200`(상한 위는 자물쇠) · 증거금 현금의 `10·25·50·100%`(최소 1,000) · 손절 `없음/−10/−25/−50/−75%` · 익절 `없음/+25/+50/+100/+200/+500%`(ROE 기준).
- 기본값: 배율 10배, 증거금 25%, 손절·익절 없음. 기질이 기본값을 바꾼다(3.14).

| 항목 | 공식 |
|---|---|
| 명목 금액 | `N = 증거금 × 배율`, 포지션 하나의 상한 **2억** |
| 수수료 | 진입·정리 각각 `N × 0.04%` |
| 100% 선택 시 증거금 | `floor(현금 / (1 + 배율 × 0.0004))` |
| 손익 · 수익률 | `PnL = 방향 × (현재가 − 진입가) / 진입가 × N`, `ROE = PnL / 증거금` |
| 청산가 | 롱 `진입가 × (1 − 증거금/N + 0.001)`, 숏 `진입가 × (1 + 증거금/N − 0.001)`. 닿으면 증거금 전액 소멸 |
| 정리 | `현금 += max(0, 증거금 + PnL − N × 0.0004)` |
| 손절·익절가 | `진입가 × (1 + 방향 × ROE / 배율)`. 닿으면 그 값에 정리. 같은 틱(또는 같은 봉)에 청산가도 넘었으면 청산이 우선 |
| 펀딩비 | 정산마다 `N × 0.001%`. 오프라인에도 전 구간 붙는다(8시간 = 명목의 0.16%) |
| 추가 진입 | 같은 방향·같은 배율만. 새 진입가 = `(N1 + N2) / (N1/진입가1 + N2/현재가)` |
| 급변(`viaJump`) | 한 정산 동안 그 종목이 평소(지나간 24시간)의 3배 넘게 움직임 |

- ROE −70% 아래면 포지션 줄이 깜빡이고 `marginCalls` +1.
- 시장 상태가 '지연'이면 진입을 막고(정리·손절 설정은 예약), '정지'면 포지션을 얼린다(손익·청산·펀딩비 없음).

### 3.13 오프라인 따라잡기
1. 돌아오면 서버 시각과 떠난 틱을 견준다. 60초 이하는 1초 틱을 받아 그대로 재생한다(경제 포함).
2. 60초를 넘으면: **포지션**은 떠난 틱부터 지금까지 1분 봉(고가·저가·종가)으로 전 구간 처리한다. 한 봉 안에서는 포지션에 불리한 쪽을 먼저 본다(롱: 저가 → 고가). 순서는 청산 > 손절 > 익절. 펀딩비는 180틱 경계마다. 시장 정지 구간의 봉은 건너뛴다.
3. **경제**는 정산 `2 + idle 단계`회분만(0단계는 0회), 떠난 직후 순서로 처리한다. 어느 곳이든 연체가 한도 − 1이 되는 정산 앞에서 멈춘다. 급매는 그때의 봉 종가로.
4. 청산으로 3.6의 즉시 파산 조건이 되면 그 시각에 파산이 정해진다(`offline = true`, `awayHours`).
5. "자리를 비운 사이" 시간표를 먼저 보여 준다(8.6). 파산이면 시간표 → 엔딩.
6. 서버 기록 보관 기간(1분 봉 90일)보다 오래 비웠으면 남은 포지션은 마지막으로 남은 봉의 종가에 정리한다 [제안].
- 나갈 때(앱이 가려지는 순간) 열린 포지션이 있으면 속보 띠에 사실 한 줄: `열어 둔 포지션 2개 — 자리를 비워도 계속 움직입니다. 가장 가까운 청산가까지 0.4%`.

### 3.14 세대 — 대물림 = 환생(프레스티지) [사용자 확정: 대물림·세 갈래·시작 빚 20만 이상·"클리커답게" / 제안: 공식·숫자][시뮬 필요]
방치형 클리커의 환생 구조(Cookie Clicker의 천상의 칩, AdVenture Capitalist의 엔젤, Egg, Inc.의 영혼의 알)를 상속 제도에 입힌다. **세대를 끝낼수록 영구 재화가 쌓여 다음 세대가 빨라진다.** 빚은 어느 갈래든 20만 이상에서 시작한다.

- 1세대는 엄마(도토리 금융 위기, 사고는 화면 밖). 플레이어는 **2세대**: 현금 10만, 캐피탈 15만, 오소리 15만, 텐트, 0단계, 선택 없음("상속을 포기할 수 있는 기간은 석 달이었다. 아무도 알려 주지 않았다."). 3세대부터 고른다. 2세대에는 이자 유예가 없다(첫 정산부터 이자 9,000).
- 세대가 넘어갈 때: "세월이 흘렀다. 우편함에 나뭇잎 통지서 한 장 — 상속 개시." 사유는 쓰지 않는다.

**(1) 영구 재화 — 가훈** [확정 2026-11-25 사용자: 이름 = 가훈. 아래 본문의 "한"은 가훈으로 읽는다]
"빚은 포기할 수 있어도 한은 포기할 수 없다." 세대가 끝날 때(파산·은퇴) 그 세대의 성과가 **한**으로 바뀐다. 한은 사라지지 않고, 가문 특성 트리(4)에 쓴다.

```
세대 성과  = floor(4 × sqrt(최고 순자산⁺ ÷ 10만))     ← 순자산이 음수면 0
           + floor(2 × sqrt(누적 채굴 기준가 ÷ 10만))
           + (그 세대의 엔딩이 새 엔딩이면 5, 은퇴면 8)
받는 한    = floor(쌓인 성과 × 장부 배수 × 반복 감쇠 × 족보 배수 × 갈래 배수)
장부 배수  = 1 + 0.01 × 가문 장부에 모은 엔딩 수        ← 200쪽이면 3배. 수집 = 강해짐
반복 감쇠  = 그 세대의 엔딩이 이미 가진 것이면 0.7^(그 엔딩을 얻은 횟수 − 1), 하한 0.3. 새 엔딩이면 1
족보 배수  = 1 + 0.05 × 트리 '족보' 단계
갈래 배수  = 상속포기 1.0 / 한정승인 0.5 / 단순승인·증여 0 (받지 않고 '쌓인 성과'로 이월)
```
- **왜 제곱근인가**: 재산은 설비 덕에 기하급수로 큰다(SIM_v2: 6세대에 3~10억). 한이 재산에 비례하면 한 세대에 트리가 끝난다. 제곱근이면 재산이 100배가 되어야 한이 10배다.

| 최고 순자산 | 성과(재산 항) | 누적 채굴 | 성과(채굴 항) |
|---|---|---|---|
| 20만 | 5 | 10만 | 2 |
| 100만 | 12 | 100만 | 6 |
| 1,000만 | 40 | 1,000만 | 20 |
| 1억 | 126 | 1억 | 63 |
| 10억 | 400 | 10억 | 200 |

- **이월**: 단순승인·증여는 한을 받지 않는다. 그 세대의 성과는 '쌓인 성과'에 남는다(최고 순자산은 이어진 세대들 가운데 최댓값, 누적 채굴과 엔딩 점수는 합). 다음에 포기나 한정승인을 하면 쌓인 것 전부로 계산한다. 단순승인은 손해가 아니라 **환생을 미루는 것**이다.

**(2) 세 갈래** — 파산 엔딩 뒤 재산 명세서에서 고른다. 시간 제한·권유 문구 없음.
| | 상속포기 = 완전 환생 | 한정승인 = 반쪽 환생 | 단순승인 = 이어 하기 |
|---|---|---|---|
| 받는 한 | **쌓인 성과 × 1.0** | 쌓인 성과 × 0.5 (나머지는 버려진다) | 0 (성과는 이월) |
| 종목 쳇바퀴·설비 | 없음 | **소액 보호**: 도토코인 쳇바퀴 + 부모가 가진 설비 중 가장 낮은 단계 1대. 나머지는 경매(설비 50%, 지갑 90%) | 남은 것 전부 + **가업 간판**(부모가 가져 본 가장 높은 단계의 한 단계 아래 설비 1대, `inheritedSign`) |
| 업그레이드(3.4a) | 0 | 남은 쳇바퀴·설비에 붙은 것 + `glove`·`shoes` 절반 | 붙은 것 그대로, `glove`·`shoes` 절반, `fee` 0 |
| 집 | 텐트 | 부모 집이 창고 이상이면 오두막, 아니면 텐트 (경매 70%) | 부모의 집 그대로 |
| 지갑·현금 | 지갑 0, 현금 7만 | 지갑 0, 현금 7만 + 경매 잉여금(빚을 갚고 남은 것) | 지갑 그대로, 남은 현금 + 3만 |
| 선물 계좌·배율 상한 | 없음(다시 연다) | 없음(다시 연다) | 물려받는다 |
| 물려받는 빚 | 0 | 0 (경매로 갚을 만큼만 갚고 끝) | 승계. 사채는 실제 빌린 원금만, 금리 상한 4%, 합계 상한 `30만 × min(3, 1 + 연속 단순승인 횟수)`(넘으면 비율대로 줄임), 처음 정산 3회 이자 유예 |
| 내 이름의 빚 | 학자금 15만(캐피탈 2%) + 연대보증(오소리 4%) = 부모 사채 잔액의 50%, 5만~15만 | 같음 | 승계 빚 + 세금이 20만에 못 미치면 학자금으로 채움 |
| **시작 빚** | **20만 ~ 30만** | **20만 ~ 30만** | **20만 ~ 90만 + 세금** |
| 세금 | 없음 | 없음 | 순재산(설비·집 평가액 + 지갑 + 현금 − 승계 빚)의 30만 초과분 × 30%, 기한 정산 8회 |
| 채권처 | 떼인 곳은 **원한**(한도 −50%, 금리 +1%p, 한 세대) + 독사 전단지 두 배 | 떼인 곳은 원한 | 빚을 이어받은 곳은 **연줄**(한도 +20%, 첫 대출의 첫 이자 면제) |
| 시작 단계 | 0 (트리 '물려받은 쳇바퀴'가 있으면 1) | 1 | 1 또는 2 |

**언제 무엇이 이득인가** — 명세서는 숫자만 보여 주고 계산은 플레이어가 한다.
| 상황 | 가장 나은 갈래 | 이유 |
|---|---|---|
| 쌓인 성과로 받을 한이 가진 한의 절반을 넘고, 남은 설비가 승계 빚을 못 버틴다 | 상속포기 | 한을 전부 받는다. 빚도 20~30만으로 가볍다. 트리에 바로 쓰면 다음 세대가 처음부터 빠르다 |
| 부모가 집(창고 이상)이나 설비를 든 채 망했고 빚이 그 값을 넘는다(흑자 도산·관계 파산) | 한정승인 | 오두막 + 쳇바퀴 + 설비 1대로 1단계에서 시작하고 한도 절반은 받는다. 포기보다 첫날이 빠르고 단순승인보다 빚이 가볍다 |
| 남은 설비의 정산 순수입이 승계 빚 이자와 세금을 넘고, 받을 한이 가진 한의 10~20%뿐이다 | 단순승인 | 가업이 계속 돈다. 재산이 커질수록 제곱근으로 성과가 쌓이므로 더 키운 뒤 환생하는 편이 낫다 |
| 2대 넘게 단순승인을 이어 승계 상한이 60~90만으로 올랐다 | 포기 또는 한정승인 | 빚이 무거워지고 쌓인 성과가 크다. 환생할 때다 |

- **은퇴(증여)**: 빚 0이고 오두막 이상이면 전광판에서 "은퇴하고 물려주기". 엔딩 없음(성과에 +8). 단순승인과 같은 '이어 하기'다: 전부 그대로 받고 기질 '금수저', 순재산 30만 초과분의 30%가 세금 빚(기한 정산 8회), 시작 빚이 20만에 못 미치면 학자금으로 채운다. 한은 받지 않고 이월한다.

**(6) 그 밖에 대를 넘는 것**
- **항상 남는 것**: 가문 장부, 가문 최고 재산, 한과 트리, 정보 수첩, 유품함, 기질(부모 1 + 조부모 1), 마을의 흔적, 가계도.
- **기질** — 부모가 망한 원인에서 하나(이야기와 기본값의 변화. 성장은 트리가 맡는다). 같은 원인으로 2대 연속이면 '진한 피'(두 효과 1.5배).

| 부모의 원인 | 기질 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| 청산 | 한 방 체질 | 100배 이상 수수료 절반, 계좌를 열면 상한 50배부터 | 배율 기본값 50배(상한 안에서), 손절 기본값 '없음' |
| 낚임 | 의심병 | 말풍선 옆에 그 출처의 가문 적중률 숫자 | 속보가 3초 늦게 뜬다 |
| 사채 | 빚 내성 | 독사 선이자 40% → 30% | 독사 골목이 처음부터 열려 있다 |
| 제도권 | 서류 체질 | 담보인정비율 80% → 85% | 금리 인상 때 이자 2.5배 |
| 유지비 | 허세 | 집 단계별 한도 +20% | 생활비·유지비 +20% |
| 압류 연쇄 | 장사꾼 피 | 설비가 캐는 값 +10% | 딱지가 연체 예고 때(1회 일찍) 붙는다 |
| 관계 | 외톨이 | 1회 줍기·채굴량 +10% | 친구 소문이 절반만 들린다, 절교한 친구의 시작 신뢰 60 |
| 대물림 | 굳은살 | 1회 줍기·채굴량 +15% | 재산 명세서의 한 줄이 가려진다 |

- **유품**: 원인 8종에 하나씩, 그 원인의 엔딩을 5 / 15 / 30종(원인별 엔딩이 15종 이하인 곳은 3 / 6 / 9종) 모으면 1 / 2 / 3단계가 되는 **수집 표식**이다. 성장 효과는 한과 트리가 맡으므로 유품의 효과는 **전당**(3.5: 단계별 5만 / 15만 / 40만)뿐이다 [제안 — 앞 설계의 유품 효과·장착 칸·단골 보너스는 트리로 합쳤다].
- **고리 끊기**(참된 끝): 빚 없는 은퇴 2대 연속 + 그다음 세대가 세금을 기한 안에 완납 → 장부 맨 뒤에 한 장. 그 뒤에도 게임은 계속된다.

### 3.15 엔딩 — 원인 × 상황 [사용자 확정: 틀·200종·대용 조건 0·읽히는 단서·연출표]
**원인 8가지**(`endings_v2_map.csv`의 `cause`, 여러 개면 그중 어느 것이든)
| 코드 | 원인 | 첫 원인 기준 수 | 기본 엔딩(조건 0) |
|---|---|---|---|
| LIQ | 청산 | 44 | END-158 |
| TIP | 낚임 | 15 | END-163 |
| SHARK | 사채 | 40 | END-041, END-097 |
| BANK | 제도권 | 33 | END-018 |
| UPKEEP | 유지비 | 8 | END-039 |
| SEIZE | 압류 연쇄 | 15 | END-087 |
| FRIEND | 관계 | 30 | END-101 |
| LEGACY | 대물림 | 15 | END-024 |

**원인을 정하는 순서**(위에서부터 처음 맞는 것)
1. 절교 3명 → FRIEND
2. 청산 직후 즉시 파산이거나, 이번·직전 정산의 거래 실현 손실 ≥ 마지막 미납액 → 그 손실 포지션에 `tipSource`가 있으면 TIP, 없으면 LIQ
3. 마지막 연체처가 세무서이거나, 남은 빚의 절반 이상이 승계 빚·세금 → LEGACY
4. 최근 정산 3회 안에 압류가 있었고 압류로 준 정산 수입 ≥ 마지막 미납액 → SEIZE
5. 마지막 연체처가 생활비·유지비 → UPKEEP
6. 조합·캐피탈 → BANK, 오소리·독사 → SHARK

**고르는 규칙**: 원인이 맞고 조건이 전부 참인 엔딩을 모은다 → 미수집 중 조건 수가 많은 것 → 희귀도 높은 것 → 번호 작은 것. 전부 수집한 것뿐이면 같은 순서로 하나를 다시 보여 주고 횟수 +1. 조건을 무시하고 주는 장치는 없다.

**플레이 중에 결말이 보이게**
- **사건 기록**: 중요한 행동을 최근 12개까지 남긴다(4.9의 종류). 조건 `last`·`last3`의 재료이자 엔딩 카드의 "마지막 세 장면".
- **이대로 가면**: 기록관 등불. 지금 파산한다고 가정했을 때 고를 엔딩이 미수집이면 켜진다. 기록관 맨 위에 `이대로 가면 → END-043 · ??? (독사 대부에게 빌린 직후 파산)`.
- **조짐 3단계**(원인별 조짐 → 경고 → 직전): SKELETON_v2 7.5의 표 그대로(배율 딱지·출처 꼬리표 → ROE −70% 깜빡임 → 청산가 꼬리표 / 원금 표시 → 연체 딱지 → 채권자가 일터 앞에 섬 등).
- **한 끗 차이**: 조건 하나만 달랐으면 받았을 미수집 엔딩 최대 2개.
- **다음 세대에 남는 것**: 기질, 유품 변화, 마을의 흔적(CSV `next_gen_trace`).

**연출**(`endings_direction.csv` 200줄 — 자세·표정·장면 크기·소품·배경·행동·장면 종류·영문 프롬프트)
- 그림은 통지를 받는 순간이 아니라 **결과가 벌어진 뒤의 삶**이다 [사용자 확정]. 장면 종류: 결과 뒤의 삶 159 · 사채업자 처리 직전 19 · 빈자리(죽음 암시) 13 · 영원한 노역 5 · 대물림(아이) 4. `eternal_labor = Y` 9개, `death_implied = Y` 13개(6.5%), `risk` 높음 4개(END-053·060·068·090 — 등급 신청 때 교체 후보).

### 3.17 톤·잔혹 수위·그림·화면 방향 (요약. 원문이 우선)
1. 캐릭터는 귀엽다 / 제도·숫자·문구는 현실 그대로 / 결과는 현실처럼 잔혹하다. 금융 용어는 진짜로 쓴다(화폐 이름만 도토리).

7. **화면 방향 = B 말랑한 잎사귀 버블** [사용자 확정]: 둥근 파스텔 버블, 흰 테두리, 젤리 버튼. **거래 화면의 차트는 깨끗한 사각 영역**이고 어떤 장식도 그 안으로 들어오지 않는다.
8. 상승 빨강 / 하락 파랑(한국 관례)이 기본, 전광판 설정에서 바꾼다. 색만으로 뜻을 전하지 않는다(▲▼, 딱지 모양, 글자).

### 4.10 통계 키 (엔딩 조건 136개 + 새 키) — 뜻
범위: [순] 파산 순간 / [세] 이번 세대 누적 / [가] 가문 누적. 마지막 청산·손실 포지션의 값은 그 포지션에서 읽는다.
| 묶음 | 키 = 뜻 |
|---|---|
| 사는 곳·때 | `house` 집 단계 · `houseInherited` 물려받은 집에 사는가 · `netWorthAtMove` 마지막 이사 때 순자산 · `time` 아침/낮/저녁/밤 · `settleNo` 이번 세대 정산 횟수 · `event` 진행 중인 게임 안 사건 · `econ` 3.12 · `nightTaps` 밤 회차의 탭 수[세] · `minSinceFamilyRecord` 가문 최고 재산을 갱신한 뒤 지난 분 |

시세(최근 600틱의 가격·거래량·매수 비율, 정산 봉 최근 480개 — 접속할 때 서버에서 받는다) · 시장 상태 · 떠오르는 숫자·말풍선·연출 상태 · 연결 상태 · 탭 속도 창.

### 5.3 파생값 (저장하지 않고 계산)
순자산 · 지갑 평가액 · 다음 정산 수지(캔 값·전기세·이자·생활비) · 종목별 지금 순수입과 역마진 여부 · 캐피탈·조합 한도 · 진행 단계(`stage` = 종목 쳇바퀴가 없으면 0, 있으면 1, 선물 계좌가 열렸으면 2) · 살 수 있는 업그레이드 표시 · "이대로 가면" 엔딩 · 숏으로 지킨 비율 · 받을 한(세 갈래별) · 신용점수.

### 5.4 엔진의 모양
순수 함수: `step(state, input) → state`. 입력은 `{ type: 'tick', tick: Tick } | { type: 'bars', bars: Bar[] } | { type: 'action', … }`. 엔진은 네트워크·시계·DOM을 모른다. 난수는 저장된 시드를 쓴다(제안 추첨·사건 추첨·리딩방).

## 6. 서버 — 시세 릴레이 [사용자 확정: 구조·출처 / 제안: 세부]

### 6.1 구성
```
Hyperliquid 공개 WS(키 없음) ─┐
DEX 체결가(RPC)             ─┴▶ [어댑터 ×2] ▶ [자동 전환] ▶ [변환기] ▶ [틱 기록] ▶ [방송 WS] ▶ 앱
                                                                    └▶ [REST: 틱·봉·시각·랭킹]
```
- 구현: Node.js + TypeScript, `ws`, HTTP는 내장 또는 Fastify, 저장은 SQLite(`better-sqlite3`, WAL) [제안]. 프로세스 하나. 폴더 `server/`.
- 위치: 미국·캐나다 온타리오 밖(서울·도쿄·싱가포르 중 한 곳). 대기 서버는 다른 나라.

### 6.2 받기 (서버 ↔ Hyperliquid)
| 항목 | 규칙 |
|---|---|
| 주소 | `wss://api.hyperliquid.xyz/ws` |
| 구독 | 종목마다 `{"method":"subscribe","subscription":{"type":"bbo","coin":"BTC"}}` — BTC·ETH·SOL·DOGE·XRP. 거래량·체결 방향은 `{"type":"trades","coin":…}` |
| 표본 | 1초마다 그 초의 마지막 `mid = (bid + ask) / 2`. 갱신이 없으면 직전 값(수익률 0). 그 초의 체결량 합과 매수 체결 비율 |
| 살아 있음 | 주기적으로 `{"method":"ping"}`. 5초 동안 아무 메시지도 없으면 끊김 |
| 재연결 | 1 → 2 → 4 → … 최대 30초(±20%). 붙으면 구독을 다시 보낸다 |
| 쓰지 않는 것 | `allMids`(폐지 예정, 15초에 1회) |
| 보조 출처 | 풀의 Swap 이벤트를 RPC로 구독해 1초마다 마지막 체결가. 평소에는 받아만 두고 주 출처의 이상 여부를 견준다 |

### 6.3 자동 전환과 시장 상태
| 조건 | 동작 | 앱에 보이는 상태 |
|---|---|---|
| 주 출처 5초 조용 | 보조로 전환. 가상 가격은 직전 값에서 이어 붙인다 | `open` (끊김 안 보임) |
| 주 출처의 1초 수익률이 보조와 30초 넘게 0.5%p 이상 어긋남 | 보조로 전환, 운영자 알림 | `open` |
| 주 출처 60초 정상 | 주 출처로 복귀(이어 붙임) | `open` |
| 두 출처 모두 5초 조용 | 가격 멈춤, 진입 막음 | `delayed` |
| 두 출처 모두 60초 넘게 조용, 서버 재시작 | 시장 정지: 포지션 얼림. 다시 열 때 멈추기 직전 가격에서 이어 붙인다(멈춘 동안의 실제 움직임은 버린다) | `halted` |
- 어느 출처였는지와 정지 구간은 틱 기록에 남긴다(앱에는 상태만 보낸다).

### 6.4 변환
- `가상 가격(t) = 가상 가격(t−1) × mid(t) / mid(t−1)`. 최초 가동 때 `markets.json`의 `startPrice`에서 시작한다.
- 지수 JQQ: `JQQ(t) = JQQ(t−1) × (1 + 다섯 종목 1초 수익률의 평균)`.
- 기준 다시 잡기(주 1회 가격대 재설정)는 **MVP에서 하지 않는다** [제안]. 프로토콜에 `epoch` 자리만 둔다(13장 T-11).
- 틱 번호 `n` = 서버 기준 시각(고정)부터의 초. 정지 중에도 n은 흐르고 상태만 `halted`다.

### 6.5 저장
| 표 | 내용 | 보관 |
|---|---|---|
| `raw_ticks` | 실제 mid·출처·체결량(서버 밖으로 나가지 않는다) | 7일 |
| `ticks` | `n, ts, st, src, [가격, 거래량 지수, 매수 비율] × 5` (1초) | 30일 |

### 6.6 앱과의 프로토콜
**WebSocket `GET /v1/stream`** — 1초에 메시지 1개. 압축 켬.
```jsonc
// 붙자마자 한 번
{ "t": "hello", "n": 8123456, "ts": 1764050000, "epoch": 1, "st": "open",
  "markets": ["DTC","BTH","SMS","MDT","JQQ"],
  "warm": { "res": 180, "bars": { "DTC": [[n0,o,h,l,c,vol,buy], …최근 480개], … } },   // 정보 규칙의 준비 구간(24시간)
  "avg": { "DTC": { "vol180": 1.0, "range180": 0.0021, "range300s": 0.0026 }, … } }     // '평소' 값
// 매초
{ "t": "k", "n": 8123457, "ts": 1764050001, "st": "open",
  "p": { "DTC": [68008.5, 1.2, 0.61], "BTH": [3401.2, 0.8, 0.44], "SMS": […], "MDT": […], "JQQ": [520.31, 1.0, 0.5] } }
//        [가상 가격, 거래량 지수(평소 = 1), 매수 체결 비율 0~1]
// 2단계 자리: "iv": { "DTC": 0.00012, … }  (없으면 무시)
```
**REST**
| 요청 | 응답 | 쓰임 |
|---|---|---|
| `GET /v1/time` | `{ n, ts, st, epoch }` | 돌아왔을 때 얼마나 비웠는지 |
| `GET /v1/ticks?from=n1&to=n2` (최대 600) | 1초 틱 배열 | 60초 이하 끊김 메우기 |
| `GET /v1/bars?res=60&from=n1&to=n2` (최대 20,000개, 넘으면 `next`) | 1분 봉 + 정지 표시 | 오프라인 따라잡기(포지션 전 구간) |
| `GET /v1/bars?res=180&from=&to=` | 정산 봉 | 비운 구간 차트, 경제 정산 2회의 급매 가격 |
| `POST /v1/rank/submit` | 검증 결과 | 6.7 |
| `GET /v1/rank?board=peak\|barehand\|ledger\|chain&around=deviceId` | 순위 | 전광판 |
| `GET /healthz` | 출처 상태, 마지막 틱 | 운영 |
- 앱은 3초 동안 틱이 없으면 '시세 지연'(진입 막음, 정리·손절 설정은 예약), 재연결은 1 → 2 → 4 … 최대 30초. 앱이 가려지면 연결을 닫는다. 서버에 아예 못 붙으면 마을은 그대로 하고(정산은 기기 시계의 틱으로) 거래 탭은 "시장에 연결할 수 없습니다", 포지션은 얼린다.
- 앱이 받는 어떤 메시지에도 실제 가격·실제 종목 이름·출처 이름이 없다.

### 6.7 랭킹 검증 (기록 검증형) [제안]
- 계산은 앱이 한다. 제출: `{ deviceId, name, board, generation, branch, peakNetWorth, ledgerCount, tradeLog[], summary: { taps, settles, minedValue, startTick, endTick }, saveVersion }`.
- 서버 검사: ① 체결가가 그 틱의 서버 가격과 같은가(오프라인 처리분은 그 1분 봉의 고가·저가 안인가) ② 진입과 정리 사이에 청산가에 닿은 틱이 있었는데 청산이 빠지지 않았는가 ③ 틱 번호가 시간 순서인가 ④ 손익 합계가 맞는가 ⑤ 상한 검사: 탭 ≤ 12회/초 × 접속 시간, 채굴 누적 ≤ 설비 표와 업그레이드로 가능한 최대, 배율 ≤ 200, 명목 ≤ 2억. 하나라도 어긋나면 올리지 않는다.
- 서버 권위 체결(주문을 서버가 체결)은 상금·보상이 걸릴 때의 2차 과제다.

### 6.8 운영·법무 메모
- Hyperliquid 약관 사본(날짜 포함) 보관, 속도 제한을 우회하지 않는다(연결 1개, 구독 10개). 원본 틱은 서버 밖으로 내보내지 않는다. 개인정보는 익명 기기 번호와 닉네임뿐.
- 틱이 5초 끊기면 알림. 출시 전 확인할 것은 13장 T-12~T-14.

### 8.2 마을과 일터 무대 (S1)
- 스크롤 없는 풍경 한 장. 건물 9곳(조합·캐피탈·전광판 / 기록관·내 집·친구네 골목 / 오소리·일터·독사 골목)과 흙길. 이름표에 원금 줄임 표기·연체 딱지. 내 집 옆에 **조상 돌탑**과 우편함, 집 문패와 쳇바퀴 간판에 **가문 문장**. 부모의 결말이 남긴 **흔적**(빈 집터의 '매물' 팻말, 남의 간판, 닫힌 친구 집, 광장의 전단지).
- **일터 무대**(화면 아래 390×136 전체가 누르는 영역):

| 단계 | 무대 | 누르면 |
|---|---|---|
| 0 | 숲길, 흩어진 도토리. 칩멍크 키 128 | 허리 숙여 줍는다 + 도토리 한 알 + `+27` + 현금 |
| 0 → 1 | 200회에 '쳇바퀴 팝니다' 팻말과 [도토코인 쳇바퀴 10,000] 버블 | 사면 쳇바퀴가 놓이고 칩멍크가 올라탄다 |
| 1~ | **종목별 쳇바퀴가 나란히 돈다**(최대 4대, 색·간판으로 구분: 도토리 갈색 / 밤 보라 / 발바닥 노랑 / 반듯한 파랑). 각 쳇바퀴 뒤에 붙은 설비(보조 쳇바퀴, 알바 햄스터, 줄, 발전기…)가 겹쳐 보이고 헛간 이상은 무대 배경이 바뀐다 | 올라탄 쳇바퀴가 돌고 그 종목 색의 코인 조각이 지갑 알약으로 날아간다. 다른 쳇바퀴를 누르면 옮겨 탄다 |
| 표시 | 역마진인 쳇바퀴에 붉은 **'역마진' 딱지**, 꺼진 쳇바퀴는 멈춰 있고 회색. 가압류 딱지(채권처 색). 업그레이드가 축의 반짝임·살의 굵기·계량기로 보인다 | |
| 압류 | 수레가 쳇바퀴째 실어 간다. 바닥에 자국이 남는다. 전부 실려 가면 0단계 무대 | |
- 칩멍크의 몸: 목끈(가문 특성 `grip` 색), 장갑(`glove`), 운동화(`shoes`), 지갑 주머니(1단계), 계좌 통지서(2단계), 설비 최고 단계의 소품 하나(알바 = 호루라기, 발전기 = 안전모, 헛간 = 작업복, 발전실 = 조끼, 공장 = 넥타이). 형편은 표정으로(연체·청산 근접이면 달리면서 식은땀).
- **일터 패널**(일터 팻말을 누르면 올라오는 버블. 세 묶음을 가로로 넘긴다):
  1. **지갑**: 종목별 수량·환산값·세대 시작 대비 등락, [전부 팔기] [절반], '캐는 즉시 팔기' 스위치, `캐는 값 비중: 도토코인 60% · 멍도토 40%`.
  2. **설비**: 종목 쳇바퀴 4칸(잠긴 것은 조건이 보인다: "누적 채굴 20,000어치 — 지금 12,400") → 사다리 7줄(대수 n/3, 다음 값, 붙일 종목 고르기, 설비별 캐는 값·전기세·지금 순수입, [끄기], 역마진 딱지, "주소지가 필요합니다(오두막 이상)").
  3. **업그레이드**: 줄마다 이름·단계·효과(`+3% → +6%`)·다음 값(줄여 쓴 숫자 `1.2만`). **살 수 있는 줄에는 초록 점**, 일터 팻말에도 점. 길게 누르면 연속 구매.

### 8.3 장소 방문 — 창구 (S2)
건물을 누르면 칩멍크가 걸어가고 화면이 다가간 뒤 창구 버블이 올라온다. HUD와 탭 바는 그대로.
| 장소 | 내용 |
|---|---|
| 금융 4곳 | 인물 흉상 + 말풍선(말투는 톤 4장) + 원금/한도 + "정산 이자 2% = 3,000" + 연체 칸 + **[도장]**(주 행동) [빌리기](보조) + 배수 칩 + 약관 보기. 독사: "받는 돈 12만 / 장부 20만", 두 번째부터 연락처 동의 칸. 원한이면 차가운 말투와 깎인 한도, 연줄이면 반가운 말투 |
| **채권자의 방문** | 정산 뒤 제안이 오면(3.5) 그 인물이 **일터 앞까지 걸어와** 말풍선을 띄운다([받는다] [거절]). 연체 '직전' 단계에서는 오소리·독사가 일터 앞에 서 있다. 압류 때는 수레와 함께 온다. 독사의 정보·족제비의 추천도 같은 방식 |
| 캐피탈 — 선물 계좌 | 조건이 차면 창구에 [선물 계좌 개설]. 사전교육 3장(족제비의 말: 레버리지 / 청산가 / "내려도 벌 수 있습니다") → 모의거래 한 번(가짜 돈으로 진입·정리) → 예탁금 확인 → 통지서. 끝난 거래 10건 뒤 [고위험 거래 확인서] 도장 |
| 조합 — 세무서 창구 | 세금 빚, 기한 타이머, [납부 도장]. 밤에는 "영업이 끝났습니다" |
| 친구네 골목 | 집 문 5개. 신뢰 막대, 빌리기·갚기, 절교하면 닫힌 문 |
| 내 집 | 매물 게시판(5단계, 드는 돈, 생활비, 막힌 이유) |

### 8.4 거래 탭 (S3) — 한 화면, 팝업·스크롤 없음
위에서부터: 종목 꼬리표 5개(등락 %, 포지션 점) → 시세 줄(현재가, 쓸 수 있는 현금, 지금 장 `잔잔함/보통/격동`) → **차트(깨끗한 사각 영역 — 장식·얼굴·말풍선이 들어오지 않는다)**: 세로축 자동 맞춤, "화면 전체 0.06%", 진입가 실선·청산가 붉은 점선·손절익절 점선, 화면 밖이면 가장자리 꼬리표 → 포지션 줄(ROE 가장 크게, 출처·빌린 돈 꼬리표) → `지갑 도토코인 12,400어치 — 숏으로 지킨 비율 0%` → 배율 8칸 눈금자(상한 위는 자물쇠, 100·200은 붉은 눈금) → 증거금 칩 + 안내 한 줄("증거금 25,000 · 수수료 250 · 청산가 65,348(−3.9%)") → 손절·익절 → [롱 · 오른다] [숏 · 내린다] / [추가 진입] [정리하기].
- **잠긴 상태** — 탭은 처음부터 보이고 누를 수 있다.

| 단계 | 보이는 것 |
|---|---|
| 0 | 자물쇠 + "쳇바퀴를 사면 시세가 보입니다." 차트 자리는 비어 있다 |
| 1 (계좌 없음) | 차트와 시세는 **읽기 전용으로 보인다**(지갑 값을 읽어야 하므로). 주문 영역 자리에 조건 3줄: `☑ 누적 채굴 50,000어치 (지금 31,200)` · `☐ 캐피탈에서 사전교육·모의거래` · `☐ 예탁금 30,000 확인`. 다 차면 "캐피탈 창구에서 계좌를 열 수 있습니다." |
| 2 | 전부 열림. 배율 눈금자의 잠긴 칸을 누르면 조건 한 줄("끝난 거래 3건 뒤 50배 — 지금 1건") |
- 처음 세 번의 거래 설명은 차트 밖 칩멍크 말풍선. 시세 지연·시장 정지·연결 불가는 차트 위 한 줄(사각 영역 밖).

### 8.5 정산·연체·속보 (S4)
정산 결과는 속보 띠 한 줄 + 건물 머리 위 숫자. 연체 딱지는 건물·빚 알약·마을 탭 세 곳에 같은 모양. 조짐 3단계(3.15). 큰 연출은 완납·강제 청산·파산 세 번뿐.

### 8.6 자리를 비운 사이 — 시간표
돌아오면 가장 먼저 뜬다. 위에 비운 구간 전체를 한 화면에 줄인 차트, 아래에 실제 시각 순서의 사실 문장.
```
자리를 비운 사이 — 7시간 52분
  23:14  밤더리움 롱 200배를 걸어 두고 나감 (증거금 42,000)
  01:27  밤더리움 강제 청산 −42,000          ← 나간 지 2시간 13분
  01:27  도토코인 숏 100배 익절 +18,600
  (정산은 2회만 돌았습니다: 캔 값 +11,400 / 전기세 −7,980 / 이자 −18,000)
```
파산이 정해졌으면 [확인] 뒤 엔딩 카드로.

### 8.7 엔딩 카드 (S5)
정적 → 붉은 '파산' 도장 → 수집 카드(새 엔딩이면 뒤집히며 등장): 번호·원인 띠 → 그림(4:3. 없으면 원인 색 바탕 + 연출표의 `action` 문장) → 제목 → 대사 → **마지막 세 장면**(사건 기록의 마지막 3개, 시각과 함께) → **한 끗 차이**(최대 2개: `손절을 걸어 뒀더라면 → END-191 · ???`) → **다음 세대에 남는 것**(기질·흔적) → `새 엔딩` 또는 `이미 수집(3번째)` · 장부 `37 / 200` → 주 버튼 **[상속 개시]**(2세대의 첫 파산부터).
- 이 화면에서 귀여운 것은 그림 속 칩멍크뿐이다. 문구와 수치는 꾸미지 않는다. `death_implied`·처리 직전 장면도 같은 틀.

### 8.8 재산 명세서 — 상속 화면
"세월이 흘렀다…" 한 장 → 명세서. 위: 부모가 남긴 것(현금·지갑·종목 쳇바퀴·설비·집·빚 목록, 기질 '굳은살'이면 한 줄이 가려짐). 가운데: **쌓인 성과와 한 계산식**(`성과 46 × 장부 1.37 × 반복 1.0 × 족보 1.10 = 69`). 아래: 세 갈래 카드가 나란히.
| 카드 | 보이는 숫자(전부 사실, 권유 없음) |
|---|---|
| 상속포기 | **받는 한 +69** · 남는 것: 없음(가문 특성: 도토코인 쳇바퀴) · 시작 빚 230,000 · 시작 현금 70,000 · 첫 정산 예상 수지 −8,800 · 시작 단계 0 |
| 한정승인 | 받는 한 +34 · 남는 것: 오두막, 도토코인 쳇바퀴, 보조 쳇바퀴 1대 · 시작 빚 230,000 · 현금 70,000 + 잉여금 0 · 수지 −13,090 |
| 단순승인 | 받는 한 0(성과 46은 이월) · 남는 것: 전부 + 가업 간판(쳇바퀴 줄) · 시작 빚 300,000 + 세금 42,000(정산 3회 이자 유예) · 수지 +2,400 · 선물 계좌 유지(50배) |
고른 뒤(포기·한정승인) **가문 특성 트리** 화면: 가진 한, 12개 줄, 살 수 있는 것에 초록 점, [다음 세대 시작]. 트리는 전광판에서도 언제든 열린다(한은 세대 중에도 쓸 수 있다).

### 8.9 기록관(도감) · 전광판 (S6)
- 기록관: 건물 등불(이대로 가면), 맨 위 한 줄, 2열 카드 앨범(3.16), 거르기 칩, 가계도, 정보 수첩(출처별 `들은 횟수 / 맞은 횟수`), 유품함.
- 전광판: 순위(서버 4개 판 + 주민 9명 사다리, 못 붙으면 주민 사다리만) / 내 기록(세대별 끝난 방식) / 가문 특성 / 설정(이름, 색 관례, 데이터 초기화 두 번 확인, 모의 게임·가상 시세 고지, 라이선스) / [은퇴하고 물려주기](빚 0·오두막 이상일 때만, 꺼져 있으면 이유).

### 8.10 첫 실행
프롤로그 4장(위기 / 사고 / "남은 건 텐트 하나, 현금 10만, 빚 30만" / "상속을 포기할 수 있는 기간은 석 달이었다. 아무도 알려 주지 않았다.") → 일터 무대에 손가락 표시 두 번 → 줍기.

## 11. 2단계: 현물 담보 옵션 (설계 스케치 — MVP 아님) [사용자 확정 2026-11-25: "그다음은 옵션 추가. 현물도 있으니깐 현물 담보 기반 옵션 전략도 가능"]

진행 단계 3. 지갑에 캔 코인이 있으므로 **가진 현물을 담보로 한 옵션 전략**이 된다. 선물이 "빠르지만 대부분 망하는 길"이라면 옵션은 "지갑을 굴리는 길"이다 — 프리미엄을 받고 상방을 팔거나, 프리미엄을 내고 하방을 막는다.

### 11.1 여는 조건 [제안]
배율 상한 200배를 연 계좌 + 지갑 평가액 30만 이상 → **조합(부엉이 지점장)** 에서 '옵션 거래 약정'(서류 5장, 전부 읽어야 넘어간다 — 제도권은 족제비와 달리 설명을 다 한다는 농담). 가문 특성으로 조건 완화.

### 11.2 전략 — 프리셋 버튼으로만 (다리를 직접 조립하지 않는다)
| 전략 | 구성 | 담보 | 게임에서의 뜻 | 최악 |
|---|---|---|---|---|
| **커버드 콜** | 가진 코인 + 콜 매도 | 지갑의 그 코인 수량을 잠근다 | "어차피 쥐고 있을 거면 프리미엄이라도." 전기세를 프리미엄으로 낸다 | 급등하면 행사가에 코인을 넘긴다(오른 만큼 못 번다). 급락은 그대로 맞는다 |
| **보호적 풋** | 가진 코인 + 풋 매수 | 프리미엄(현금) | 숏 보험의 다른 모양. 펀딩비·청산이 없고 프리미엄이 정해져 있다 | 프리미엄만 날린다 |
| **칼라** | 풋 매수 + 콜 매도 | 코인 잠금 | 프리미엄 없이(또는 조금 받고) 위아래를 모두 막는다. 설비가 큰 가문의 "잠자는 동안의 안전띠" | 상방 포기 |
| **현금 담보 풋 매도** | 풋 매도 | 행사가 × 수량의 현금을 잠근다 | "싸지면 사겠다"고 약속하고 프리미엄을 받는다. 배정되면 코인을 받는다 — **코인을 사는 유일한 길** | 폭락해도 행사가에 사야 한다. 현금이 잠겨 이자를 못 내고 연체 |
| (뒤로) 스트래들 매수 | 콜 + 풋 매수 | 프리미엄 | 속보 '변동성 확대'에 거는 길 | 프리미엄 전부 |
| (뒤로, 독사 전용) 무담보 매도 | 담보 없는 콜·풋 매도 | 독사 대부의 '보증' | 독사가 "프리미엄을 미리 드리지요"라며 파는 상품. 손실 무한 | 대물림 |

### 11.3 값 매기기 — 옵션 시장 없이
- 실제 옵션 호가를 쓰지 않는다(약관·복잡도). **서버가 가진 틱 기록으로 계산한다.**
- 모형: 블랙-숄즈(유럽형, 금리 0, 배당 0). `콜 = S·N(d1) − K·N(d2)`, `d1 = [ln(S/K) + σ²T/2] / (σ√T)`, `d2 = d1 − σ√T`, 풋은 풋-콜 패리티.
- 변동성 `σ`: 서버가 종목별로 **지나간 24시간의 1분 로그 수익률**에서 실현 변동성을 지수 가중(반감기 4시간)으로 재고, 정산마다 `iv` 값으로 방송한다(6.6의 자리). 모든 플레이어가 같은 값을 쓰고, 랭킹 검증도 같은 값으로 다시 계산한다.
- 가격 조정 [제안]: 살 때 `σ × 1.15`, 팔 때 `σ × 0.90`(창구의 몫 — 현실의 변동성 위험 프리미엄과 호가 차이). 외가격일수록 `σ`를 조금 올린다(행사가가 1σ 멀어질 때마다 +3%). 게임이 "꼬리는 비싸다"를 가르친다.
- 행사가: 현재가 기준 `−2σ√T, −1σ√T, 0, +1σ√T, +2σ√T` 다섯 칸(종목 표기 단위로 반올림). 수량: 지갑의 `25 / 50 / 100%`(풋 매도는 현금의 %).

### 11.4 만기와 결제 — 정산 3분의 시계로

### 11.5 지갑·담보·압류·엔딩과 물리는 곳
| 물리는 곳 | 규칙 [제안] |
|---|---|
| 잠긴 코인 | 팔기·급매·전기세 차감·캐피탈 담보에서 **빠진다.** 커버드 콜을 많이 쓰면 캐피탈 한도가 줄고 전기세를 현금으로 내야 한다 |
| 잠긴 현금 | 정산 납부에 못 쓴다. "돈은 있는데 연체"(증거금에 묶인 돈의 옵션판) |
| 채굴과의 결합 | 새로 캔 코인은 잠기지 않는다. 설비가 캐는 양을 보고 "다음 8시간에 캘 만큼"을 미리 파는 버튼(채굴 선도) — 뒤로 |

| 가압류 | 받은 프리미엄도 '수입'으로 보고 30%를 뗀다 |
| 세대 | 만기가 남은 옵션은 단순승인·증여 때 그대로 넘어간다(부모가 판 콜을 자식이 넘겨준다). 포기·한정승인은 강제 청산 후 경매에 합친다 |
| 파산 원인 | 새 원인은 만들지 않는다. 옵션 손실이 미납액 이상이면 LIQ(정보 꼬리표가 있으면 TIP) |
| 엔딩 | 200종은 그대로 두고 **번외 장부(END-201~)** 를 새로 쓴다: 급등장에 코인을 넘긴 커버드 콜, 폭락장에 배정받은 풋 매도, 현금이 잠겨 연체, 독사의 무담보 매도 등 20종 안팎 — 편수와 글은 2단계 기획에서 |
| 한(恨) | 프리미엄 수입은 순자산에 들어가므로 따로 항을 두지 않는다 |

### 11.6 MVP가 남겨 둘 자리 (지금 구현에 넣을 것)
1. 지갑은 `{ qty, locked }`, 현금은 `cash`와 `cashLocked`(MVP에서는 항상 0). 팔기·급매·담보·전기세·압류 함수는 **`qty − locked`** 로 계산한다.
2. 포지션은 `kind` 구분이 있는 합집합(`'perp'`), 포지션 처리 루프는 종류별 처리기를 부르는 구조. 오프라인 따라잡기도 같은 루프.
3. 진행 단계는 숫자(`0 | 1 | 2 | 3`), 해금 조건은 데이터(`balance.progression`). 거래 탭 위쪽에 상품 전환(선물 | 옵션) 자리.
4. 서버: 1초 틱 30일·1분 봉 90일 보관(실현 변동성 계산에 충분), 방송 메시지의 `iv` 자리, 정산 봉에 `settleAvg60`(마지막 60틱 평균) 칸.
5. 체결 기록(`tradeLog`)에 `kind`와 버전. 랭킹 검증은 종류별 검사기.
6. 사건 기록 종류·통계 키·엔딩 조건 연산자는 데이터로 늘릴 수 있게(코드에 목록을 굳히지 않는다). 엔딩 번호는 200을 넘을 수 있게.
7. 압류 순서 함수는 "넘기기 전에 거는 일" 고리를 하나 둔다(옵션 강제 환매가 들어갈 자리).
8. 코인을 **사는** 함수는 만들되 화면에 내놓지 않는다(풋 매도 배정이 쓸 자리).

| T-7 | 단순승인을 이어 가는 가문이 한을 영영 안 받아도 되는가(이월만) | 그대로. 환생 시점을 고르는 것이 재미다. 다만 재산 명세서에 "쌓인 성과"를 항상 보여 준다 |

| T-11 | 가상 가격대 다시 잡기(주 1회) | MVP에서는 안 한다. 몇 달 뒤 가격대가 크게 벗어나면 세대 경계에서만 옮기는 방식으로 |
