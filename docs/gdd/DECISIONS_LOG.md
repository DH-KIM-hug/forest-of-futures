# 결정 기록 — 사용자가 자는 동안 기획자가 정한 것 (2026-11-25)

> 사용자에게 묻지 않고 정한 것을 한 줄씩 적었다. 형식: **무엇** — 왜 — 바꾸려면.
> [사용자 확정] 사항(콘셉트, 탭 2개, 종목 5개, 최대 200배, 시작 빚 30만, 엔딩 200종 번호 등)은 건드리지 않았다.
> 먼저 볼 것: 아래 "아침에 먼저 볼 10가지".

## A. 정산·이자

- **A-1 정산 주기 45초** — 후보 15·30·45·60·90·120초를 각 2,000회씩 시뮬레이션해 목표 6개를 모두 충족한 유일한 값. 60초는 방치해도 13분간 아무 일도 없어 탈락(`SIM_RESULTS.md`) — `data/balance.json` `settlement.intervalSec`.
- **A-2 정산 이자율 1% / 2% / 4% / 8%** — 기존 GDD의 3/8/15/25%의 절반 수준(1.5/3/6/10%)으로 돌려 봐도 이자가 거래 수익보다 커서 거래할수록 손해였다. 그래서 더 낮췄다 — `data/loans.json` `ratePerSettlement`.
- **A-3 납부 순서 독사 → 오소리 → 캐피탈 → 은행 → 유지비** — 연체 한도가 짧은 곳부터 막아 억울한 파산을 줄인다 — `balance.json` `settlement.payOrder`.
- **A-4 모자라면 낼 수 있는 만큼만 내고, 미납 이자는 원금에 더한다** — 원래 대화의 "미납 이자는 원금에 얹힘"을 따랐고, 카탈로그의 "연체 n회" 조건을 살리려면 즉시 파산이 아니어야 한다 — `balance.json` `overdue`.
- **A-5 연체 한도: 사채 2회, 1·2금융·유지비 3회 연속** — 한 번은 경고, 두 번째에 끝. 사채가 더 급하다 — `loans.json` `maxOverdueStreak`, `housing.json` `upkeepMaxOverdueStreak`.
- **A-6 정산 타이머는 앱이 켜져 있는 동안 어느 탭에서든 흐른다** — 거래 중에도 이자의 압박이 있어야 한다 — 엔진 틱 규칙(GDD 19장).

## B. 노동

- **B-1 일자리 6단계, 1회 수입 60 / 90 / 130 / 200 / 400 / 1,500** — 앞 4단계는 노동 횟수(150·500·1,200회)로, 뒤 2단계는 집으로 열린다. 누를수록 벌이가 느는 클리커의 성장감 — `data/jobs.json`.
- **B-2 정산 급여(0~10만)** — 방치형 장르이므로 안 눌러도 들어오는 수입이 필요하다. 오프라인 수입도 이것 — `jobs.json` `wagePerSettlement`.
- **B-3 일자리는 고르는 것이 아니라 자동으로 가장 좋은 것** — 화면 요소를 줄이려고 — `jobs.json` 문서 설명, 엔진.
- **B-4 초당 12회까지만 인정** — 자동 클릭 도구 방지 — `jobs.json` `rules.maxTapsPerSec`.
- **B-5 오소리 연체 중 수입 30% 차압(오소리 원금에서 깎임)** — 카탈로그의 차압 엔딩(END-054, 080)을 규칙으로 만들었다. 뺏기기만 하는 게 아니라 빚이 줄어 공정하다 — `jobs.json` `rules.garnishRate`.

## C. 파산

- **C-1 파산 경로 3가지: 연체 한도, 청산으로 전 재산 소멸, 친구 3명과 절교** — 카탈로그 4분류(1금융·사채·친구·청산)가 각각 실제로 일어나게 하려고 — `balance.json` `bankruptcy`.
- **C-2 강제 청산 직후 현금 + 다른 포지션 < 1,000이고 빚이 있으면 즉시 파산** — "전액 200배 → 벼락 청산" 엔딩들이 그 자리에서 터져야 한다. 없으면 빈손으로 정산을 기다리는 죽은 시간이 생긴다 — `bankruptcy.liquidationWipeout.enabled`를 false로.
- **C-3 연체 파산이라도 그 회차의 청산 손실이 미납액 이상이면 원인을 '청산'으로 본다** — 거래로 망한 사람에게 거래 엔딩을 주려고 — `bankruptcy.attributeToTrading.enabled`.
- **C-4 빚이 0이면 전 재산을 날려도 파산이 아니다** — 빚이 없는 사람은 망할 이유가 없다. 빈손으로 다시 줍는다 — `liquidationWipeout.requiresDebt`.
- **C-5 파산하면 시작 상태로 초기화, 도감·누적 통계·기록만 남는다. 회차 보상은 없음** — MVP를 단순하게. 도감 수집 보상은 나중 과제 — GDD 11.4.
- **C-6 빚이 0일 때 '은퇴'로 기록을 확정하고 회차를 끝낼 수 있다** — 부자가 된 회차를 끝낼 방법이 필요하다. 파산 엔딩은 주지 않는다 — `balance.json` `ranking.retire`.

## D. 집

- **D-1 집 5단계 이름은 카탈로그 그대로: 텐트 → 통나무 오두막 → 도토리 창고 → 호숫가 별장 → 황금 저택** — 엔딩 15개 이상과 D1 문서가 이 이름을 쓴다. 톤 문서의 현실식 6단계 표는 "참고용, 마을 설계 때 다시 쓴다"고 되어 있었다 — `housing.json` `name`(현실식 대안은 `altNameRealistic`에 넣어 둠. 바꾸면 엔딩 문구도 함께 고쳐야 한다).
- **D-2 가격 0 / 50만 / 200만 / 1,000만 / 5,000만, 유지비는 가격의 1%** — 기존 GDD의 300만~2억을 시작 빚 30만 규모에 맞춰 줄였다 — `housing.json`.
- **D-3 담보 평가액 = 가격, 1금융 한도 80%** — 기존 GDD는 300만짜리 집의 평가액이 500만이라 집을 사면 돈이 생기는 구멍이 있었다. LTV 80%는 카탈로그(END-008)에 맞춤 — `housing.json` `rules.ltv`.
- **D-4 집을 팔면 평가액의 90%, 경매는 70%** — 이사를 오르내리며 돈을 불리지 못하게 — `rules.sellRate`, `auctionRate`.
- **D-5 이사는 '내 집'을 눌러 한다(복덕방 건물 없음)** — 건물 수를 9개로 맞춰 한 화면에 44pt 이상으로 넣으려고 — GDD 4장.
- **D-6 집 단계에 따라 마을 전체 색감이 바뀐다** — "삶이 나아지는 모습이 보여야 한다"는 사용자 요구를 집 외형 한 채보다 크게 보여 주려고 — `housing.json` `villageMood`.

## E. 거래

- **E-1 시뮬레이션 시세만 사용, 실시간 연동 없음** — 바이낸스 약관·한국 IP 차단·심사 위험(R-2). 삼솔전자·SQ하이넛츠는 대응하는 실시간 종목도 없다 — `markets.json` `liveSymbol` 자리만 남김.
- **E-2 시세 모델: 추세(평균 150초) + 급등락 + 약한 되돌림, 1초 틱** — 추세가 있어야 차트를 읽는 재미와 실력 차이가 생긴다(시뮬레이션 실험 4) — `markets.json`.
- **E-3 종목당 포지션 1개, 격리 마진** — 한 화면에 다 보여야 하므로. 현금이 음수가 되지 않는다 — `balance.json` `trading`.
- **E-4 배율은 8단계(1·2·5·10·25·50·100·200)** — 슬라이더는 44pt 규칙과 한 손 조작에 맞지 않는다 — `trading.leverageOptions`.
- **E-5 증거금은 현금의 10·25·50·100%** — 금액 입력 키보드를 띄우지 않으려고(팝업 금지) — `trading.marginPctOptions`.
- **E-6 수수료 0.04%(진입·정리 각각), 정산마다 펀딩비 0.02%** — 실제 선물 거래소 수준. 200배에서는 왕복 수수료가 증거금의 16%라 고배율의 비용이 드러난다 — `trading.feeRate`, `fundingRatePerSettlement`.
- **E-7 청산 기준: 유지 증거금률 0.1%** — 200배 청산가가 진입가에서 0.4% 거리 — `trading.maintenanceRate`.
- **E-8 손절·익절은 ROE 기준 단계 선택** — 가격 입력을 없애려고 — `trading.slRoeOptions`, `tpRoeOptions`.
- **E-9 급등락 틱에서는 손절이 미끄러지고, 청산가까지 넘으면 청산이 우선** — 현실의 갭·슬리피지. 엔딩 END-154, 169, 191의 근거 — GDD 8.4.
- **E-10 같은 방향 추가 진입(물타기) 허용, 반대 방향은 정리 후에만** — 물타기 엔딩(END-155, 157)을 살리고 화면은 단순하게 — GDD 8.4.
- **E-11 장 마감 없음(24시간)** — 주식 종목도 항상 움직인다. 세션이 3~5분이라 장 시간을 넣으면 못 하는 시간이 생긴다 — 시세 엔진.
- **E-12 종목 시작가는 가상의 숫자** — 실제 시세와 무관함을 분명히 — `markets.json` `startPrice`.

## F. 엔딩 판정·도감

- **F-1 판정 방식: 원인 일치 + 조건 전부 만족 → 미수집 우선 → priority 큰 것** — 기존 명세의 우선순위(청산 > 사채 > 친구 > 1금융)와 "미수집 우선" 규칙을 그대로 구현 — `endings.json` `meta.triggerSpec`, `balance.json` `endings`.
- **F-2 완성 보장 장치: 새 엔딩 없는 파산이 3번 이어지면 미수집 proxy 엔딩을 준다** — 조건이 까다로운 엔딩 때문에 200칸이 영영 안 채워지는 일을 막으려고 — `endings.pity`.
- **F-3 86개 엔딩은 대용 조건(proxy)** — 추심 피하기 미니게임, 보증, 결혼식 같은 사건은 MVP에 없다. 각 엔딩 `trigger.note`에 무엇으로 대신했는지 적었다 — `scripts/data/build_endings.py`의 `proxy(...)` 줄.
- **F-4 기기 시각·날짜를 쓰는 엔딩 9개** (END-029 아침, 035 오후 4시 이후, 046 밤 10시 이후, 049 새벽, 080·094 새벽, 086 매월 13일, 104 주말, 136 9~11월) — "은행 셔터", "독사 생일" 같은 설정을 싸게 살리는 방법. 시계를 바꿔 얻을 수 있지만 해가 없다 — 같은 파일.
- **F-5 최대 배율이 200배이므로 카탈로그의 "50배"는 모두 "200배"로, END-194(100배 해제 이벤트)는 "생애 첫 200배"로** — 100배는 이제 평범한 선택지다 — 같은 파일 `GLOBAL`, `ov(194…)`.
- **F-6 신용점수는 표시·판정용 파생 값(한도에는 영향 없음)** — 카탈로그에 신용점수 엔딩이 있어 값은 만들되 규칙은 늘리지 않았다 — `balance.json` `credit`.
- **F-7 친구는 5명(단짝 다람쥐·절친 너구리·이웃 토끼·여우 선배·곰 형)** — 카탈로그에 "친구 5명", 절친 너구리, 단짝 다람쥐가 나온다. 주인공이 칩멍크가 되어 다람쥐 친구와 종이 겹치지 않는다 — `friends.json`.
- **F-8 절교하면 남은 빚이 독사 대부에게 넘어간다(단짝 다람쥐만 탕감)** — END-113(채권 양도), END-147(탕감하고 절교)을 규칙으로 — `friends.json` `onBreak`.
- **F-9 도감 미수집 칸에 판정 조건을 힌트로 그대로 보여 준다** — 수집이 부수 목표이므로 방법을 숨기지 않는다 — `endings.json` `hint`(자동 생성).

## G. 엔딩 문구 수정 (전체 내역: `docs/gdd/sources/endings-text-changes.md`)

- **G-1 번호·분류·개수는 그대로, 문구 151개 수정** — 대부분 기계적 치환이다: 다람쥐 → 칩멍크(주인공 종 변경), 50배 → 200배, 원 → 도토리, 오타.
- **G-2 오타 수정** — 접급 → 접근, 무조권 → 무조건, 소증 서류 → 서류, 주르 → 주로, 刻인 → 새긴, MARIN → MARGIN, 고나치고 → 지나치고, 벙뜬 → 벙찐, 메세지 → 메시지, 수경 경비원 → 경비원, 표딱지 → 딱지, 뽀록 → 들통.
- **G-3 수치를 게임 규칙에 맞춤 (11개)** — 예: END-002 "3억 원 저택, 200만 원" → "5,000만 도토리 저택, 유지비 50만", END-043 "500만 빌려 300만" → "20만 빌려 12만", END-101 "우정의 가격은 50만 원" → "5만 도토리".
- **G-4 톤 규칙 때문에 고친 것 50개, 스토리 때문에 5개** — 부록 A에 한 줄씩. 원칙: 신체 훼손·죽음 암시·감금은 재산·서류·생활의 손실로 바꾸고, 가혹함은 유지한다.
- **G-5 END-045에서 실제 나라 이름(캄보디아) 삭제** — 사용자 지시. "이름 모를 외딴 건물"로.
- **G-6 "한강" 표현 삭제(END-158, 192)** — 투자 속어에서 극단적 선택을 뜻한다. 엄마의 사고 성격이 미정인 상황에서 특히 피해야 한다.
- **G-7 "볼주머니" 표현 삭제(END-053, 078)** — 사용자가 거절한 "볼주머니 = 현금 게이지"와 헷갈리지 않게, 그리고 몸을 터는 묘사라서.
- **G-8 엄마·부모가 살아 있는 것처럼 읽히는 문구 수정(END-055, 114)** — 엄마는 세상을 떠났다는 설정과 충돌. "고향 할머니 댁", "급한 병원비라고"로.

## H. 화면·기술

- **H-1 three.js를 쓰지 않는다** — 2D 그림 교체와 간단한 이동뿐이라 3D가 필요 없고, UI는 어차피 DOM이며, 번들·발열·WebGL 손실 위험만 는다 — GDD 19장. 마을 그림을 컴포넌트 하나로 격리해 나중에 바꿀 수 있게 했다.
- **H-2 Vite + React + TypeScript + Zustand, 규칙은 화면과 분리한 순수 엔진** — 가장 흔한 조합이고 엔진을 화면 없이 테스트할 수 있다 — GDD 19장.
- **H-3 차트는 직접 그린 Canvas 2D(선 그래프)** — 선 하나와 가로선 4개뿐이고 귀여운 스킨·가장자리 꼬리표를 마음대로 하려고. Lightweight Charts는 캔들이 필요해지면 검토 — GDD 19장.
- **H-4 마을은 3×3 건물 9개, 스크롤 없음. 건물을 누르면 아래 패널이 바뀐다** — "직접 찾아간다"를 지키면서 한 손으로 다 닿게 — GDD 4장, 15.2.
- **H-5 상승 빨강 / 하락 파랑(한국 관례)** — 한국어로 먼저 내므로. 위험 표시는 색만이 아니라 딱지 모양과 글자로 구분한다 — `balance.json` `ui.priceColors`, 전광판 설정에서 바꿀 수 있게 함.
- **H-6 도감은 마을 기록관, 랭킹·설정은 광장 전광판(둘 다 전체 화면으로 열림)** — 톤 문서의 제안을 채택. 탭은 2개로 유지 — GDD 12, 13장.
- **H-7 HUD에 "다음 정산에 나갈 돈"을 항상 표시** — 이 게임의 핵심 긴장이므로 — GDD 15.1.
- **H-8 프롤로그는 글 3장, 건너뛰기 가능. 사고는 "사고가 있었다" 한 줄** — 사고 성격 미정, 화면 밖 유지 — GDD 15.2.
- **H-9 주인공 기본 이름 "칩멍크", 전광판에서 변경** — 이름이 미정이라 — `balance.json` `protagonist`.
- **H-10 랭킹은 로컬: 마을 주민 9명(30만~30억)과 내 순위** — 서버 없이도 오를 사다리가 보이게 — `balance.json` `ranking.npcs`.
- **H-11 오프라인은 최대 정산 5회분만, 연체로는 자는 사이 파산하지 않음, 청산으로는 파산** — 몇 시간 뒤 돌아왔더니 이자로 끝나 있으면 부당하다. 열어 둔 포지션은 본인이 진 위험이다(END-164, 186, 196) — `balance.json` `offline`.
- **H-12 저장은 localStorage 한 키, 어댑터로 감쌈** — MVP는 웹 빌드. 앱 포장 때 Preferences로 교체 — GDD 14.1.
- **H-13 소리·진동·표정 변화·최종 그림은 MVP에서 뺐다** — 코딩 에이전트 한 번에 만들 수 있는 범위로 — GDD 18장.
- **H-14 속보 9종 추가(금리, 부동산, 호재·악재, 가짜 속보, 세력, 지원금)** — 금리 인상·부동산 하락·가짜 뉴스 엔딩의 근거이자 고배율의 위험 요소 — `data/events.json`.
- **H-15 기존 101단계 GDD 흐름(state.json)은 그대로 두고 메타의 engine 값만 갱신** — 이 문서가 남은 단계를 통합한다. 단계를 일괄 완료 처리하지는 않았다(게이트를 거치지 않았으므로).
- **H-16 카탈로그 원본을 저장소에 복사(`docs/gdd/sources/endings-catalogue-200-2.md`)** — `endings.json`을 다시 만들 수 있어야 하므로. 원본 파일(다운로드 폴더)은 건드리지 않았다.

## N. 뼈대 v2 개정 4 — 시세 출처를 Hyperliquid로 (2026-11-25)

M장의 바이낸스 관련 항목(M-8, M-12의 출처 부분, R-19·R-23)을 대체한다. 파일: `docs/gdd/v2/SKELETON_v2.md`(개정 4), `balance_v2.draft.json`(v2-draft-4), `sim/SIM_v2.md`(개정 4), `sim/fetch_hyperliquid.mjs`, `sim/data/hl_1m.json`.

### 사용자 확정 (2026-11-25)
- **N-1 [사용자 확정] 시세 출처는 Hyperliquid 공개 WebSocket. 보조 출처는 DEX 블록체인 체결 가격(Arbitrum Uniswap v3 WETH/USDC·WBTC, Solana Orca·Raydium SOL/USDC, BNB체인 PancakeSwap WBNB/USDT — RPC 경유, 매출이 생기면 자체 노드). 서버가 자동 전환한다** — 바이낸스는 [폐기]. 서버가 받아 가공해 앱에 주는 구조(M-3), 증폭 없음(M-1)은 그대로 — SKELETON_v2 5.2~5.4.
- **N-2 [확인된 사실] `wss://api.hyperliquid.xyz/ws`에 키 없이 연결, `bbo` 5종목 구독 성공(10초에 BTC 105, ETH 93, SOL 89, BNB 41, XRP 80회). `allMids`는 폐지 예정이고 15초에 1회만 와서 쓰지 않는다. 약관(2026-06-15판)은 적용 범위가 웹 인터페이스이고 API 데이터 재가공·재배포 제한 조항이 없다(3.1.8 합리적 사용·속도 제한 우회 금지만). 제한 지역은 미국·캐나다 온타리오. 명시적 상업 허용 문구는 없다** — 약관 사본 보관, 출시 전 서면 확인 권장.

### 설계 [제안]
- **N-3 가격은 mid = (최우선 매수호가 + 최우선 매도호가) / 2 를 서버가 1초마다 표본. 가상 가격(t) = 가상 가격(t−1) × mid(t) / mid(t−1)** — 그 초에 갱신이 없으면 수익률 0. 무기한 선물 가격이라 현물과 미세하게 다르지만 수익률만 쓰므로 상관없다 — 5.3.
- **N-4 거래량·체결 방향은 `trades` 구독으로 얻는다** — 속보 규칙(거래량 급증, 대량 체결)에 필요 — 5.4.
- **N-5 자동 전환: 주 출처가 5초 조용하거나 보조 출처와 30초 넘게 0.5%p 이상 어긋나면 보조로, 주 출처가 60초 정상이면 복귀. 전환할 때 가상 가격은 직전 값에서 이어 붙인다. 두 출처 모두 60초 넘게 끊기면 시장 정지** — Hyperliquid의 지난 기록은 1분봉뿐이라 초 단위로 메울 수 없어서, 메우는 대신 넘어간다. M-9의 "60초 이하는 메워서 재생"을 대체 — 5.4, 5.5.
- **N-6 원본 틱은 서버 안에만 두고 앱에는 가공값만 보낸다. 게임 안에 "실제 시장 움직임을 가공한 가상 시세" 고지** — 한국의 데이터베이스 제작자 보호 위험 완화.

### 설계 [제안]
- **S-3 선물 개방 = 현실 제도의 패러디, 배율 상한도 단계로** — 조건: 이번 세대 누적 채굴 5만어치 + 캐피탈 '선물 계좌 개설'(사전교육 3장 + 모의거래 1회 + 예탁금 3만 확인, 떼지 않음). 상한 10배 → 끝난 거래 3건 뒤 50배 → 10건 + '고위험 거래 확인서' 도장 뒤 200배. 이유: 상한이 없으면 2세대가 첫 접속에 200배 한 방으로 33분 안에 끝난다(SIM_v2). 대가: 200배가 조건인 엔딩은 2일차 이후나 계좌를 물려받은 세대에서 나온다. 거래 탭은 처음부터 보이고 조건과 현재 값이 보인다(1단계부터 차트는 읽기 전용). 바꾸려면 `balance.progression.futures`.
- **S-4 초반 생존: 0단계(쳇바퀴 없음)는 오프라인 정산 0회, 줍기 200회 뒤 도토코인 쳇바퀴 10,000** — 줍기 27은 접속 중 정산당 −2,710이라 현금 10만으로 접속 정산 36회(약 1시간 50분)를 버틴다. 첫 쳇바퀴 목표는 첫 접속 3~6분. "노동만으로는 못 갚는다"는 유지. P-5(오프라인 2회)의 예외.
- **S-8 종목별 쳇바퀴의 값과 순서** — 도토코인 10,000(줍기 200회) → 밤더리움 30,000(누적 채굴 2만) → 멍도토 15,000(누적 채굴 5만) → 삼솔전자 60,000(오두막 이상). 거친 종목일수록 캐는 배수와 전기 배수가 함께 크다(도토코인 1.00 / 0.70, 밤더리움 1.10 / 0.78, 삼솔전자 1.20 / 0.86, 멍도토 1.30 / 0.95): 기준가에서는 더 벌고 조금만 내려도 역마진.
- **S-9 설비 사다리는 공용, 한 대씩 종목 쳇바퀴에 붙인다(옮기면 구매가의 5%)** — 전체 생산량이 SIM_v2 개정 6과 같게. 종목마다 따로 두면 대수가 4배가 된다.
- **S-10 압류 순서: 지갑 → 딱지 붙은 설비(같은 단계면 지금 순수입이 큰 종목의 것부터) → 설비가 다 떠난 종목 쳇바퀴(싼 것부터). 종목 쳇바퀴가 전부 실려 가면 0단계로 돌아간다** — R-5 보완.
- **S-11 세대 안 업그레이드 7줄: 목장갑(줍기 +4%), 운동화(채굴 탭 +3%), 기름칠·베어링(종목 설비 +2%), 관성 바퀴(혼자 도는 양), 절전(전기세 −1%), 설비 단계별 교육·정비(+2%), 단골 환전상(팔기 수수료 −0.03%p). 값 = 기준 × r^단계(r 1.10~1.15)** — 한 단계의 수익률을 같은 돈의 설비의 절반 이하로 잡아 목표 시점을 깨지 않게. 업그레이드는 붙은 것과 함께 압류되고 값은 쳐주지 않는다. 몸에 걸친 것은 압류되지 않는다.
- **S-12 영구 재화 '한(恨)': 성과 = floor(4 × sqrt(최고 순자산 ÷ 10만)) + floor(2 × sqrt(누적 채굴 ÷ 10만)) + 새 엔딩 5(은퇴 8). 받는 한 = 성과 × (1 + 0.01 × 장부 수) × 반복 감쇠(0.7^n, 하한 0.3) × 족보 × 갈래(포기 1.0 / 한정승인 0.5 / 단순승인·증여 0, 이월)** — 재산이 기하급수로 커서 제곱근. 수집할수록 배수가 크고 같은 엔딩의 반복은 준다.
- **S-13 한정승인은 반쪽 환생: 도토코인 쳇바퀴 + 가장 낮은 설비 1대 + 오두막(부모가 창고 이상일 때)을 남기고 한은 절반** — 앞 설계(K-7)의 한정승인은 포기와 거의 같아 고를 이유가 약했다.
- **S-14 가문 특성 트리 12줄(탭, 설비, 시작 현금, 물려받은 쳇바퀴, 선행 학습, 집안 내력, 금리 인하 요구권, 압류 금지 물품, 생계 수단 보호, 오프라인 정산 +1~4, 낯 두꺼움, 족보)** — 목표 곡선: 빚 청산까지 첫 세대 36시간 → 다섯째 세대 4~6시간. 가문 문장·목끈·조상 돌탑으로 보인다.
- **S-15 기질은 남기고, 유품은 수집 표식 + 전당만. 유품 효과·장착 칸·단골 +5%는 트리로 합친다** — 성장 수단이 넷(기질·유품·단골·한)이면 너무 많다. K-11은 유지, K-12는 축소.
- **S-16 `econ` 조건 키를 다시 정의: 캐는 값 비중이 가장 큰 종목이 세대 시작가 대비 −10% 이하면 slump, −30% 이하면 crash** — R-6으로 지수 기반 경기가 없어졌는데 END-131이 이 키를 쓴다. END-131에 `mineConcentration >= 80`, END-183에 `walletTopShare >= 80`을 더해 "한 종목에 몰았다가" 엔딩으로 배정(엔딩 수는 200 그대로, 빌드 스크립트의 패치 표로).

- **S-18 가상 가격대 다시 잡기(주 1회)는 MVP에서 하지 않는다** — 세대 시작가 고정과 포지션 방치가 단순해진다. 프로토콜에 `epoch` 자리만.
