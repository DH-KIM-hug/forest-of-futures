## 3. 핵심 루프

### 3.1 분 단위 루프 (한 세션 3~5분)
```
마을 탭                                거래 탭
┌──────────────────────────┐         ┌──────────────────────────┐
│ 일터에서 도토리 줍기(탭)  │  현금   │ 차트를 보고 방향·배율 선택 │
│ → 현금이 쌓인다           │ ─────▶ │ → 롱/숏 진입              │
│                          │         │ → 손절·익절 걸기           │
│ 채권처 건물로 가서        │ ◀───── │ → 정리 또는 강제 청산      │
│ 원금 탕감 도장 / 대출     │  손익   │                          │
└──────────────────────────┘         └──────────────────────────┘
              ▲                                   ▲
              └──── 45초마다 정산: 급여 → 이자 → 연체 판정 ────┘
```
1. 일터에서 누른다 → 현금이 는다.
2. 정산까지 남은 시간을 본다. 이번 정산 이자가 얼마인지 HUD에 항상 보인다.
3. 남는 돈을 (a) 원금 탕감 도장에 쓰거나 (b) 거래 탭에서 판돈으로 쓴다.
4. 돈이 모자라면 건물로 찾아가 빌린다. 빌릴수록 다음 정산이 무거워진다.
5. 정산에서 이자를 못 내면 연체. 한도를 넘으면 파산 → 엔딩 → 새 인생.

### 3.2 세션 사이 루프
- 앱을 닫아도 최대 5회 정산분의 시간이 흐른다(급여·이자·열린 포지션). 돌아오면 "자리를 비운 사이" 요약을 본다.
- 빚을 다 갚으면 → 오두막 구입 → 더 좋은 일자리·1금융 대출이 열림 → 창고 → 별장 → 저택. 마을의 집 외형과 색감이 바뀐다.
- 파산하면 처음 상태로 돌아가지만 도감, 누적 통계, 최고 기록은 남는다.
- 장기 목표: 도감 200칸, 전광판 순위(1위 독사 대부 30억 도토리).

### 3.3 한 회차의 예상 흐름 (시뮬레이션 기준, 45초 정산)
| 시점 | 일어나는 일 |
|---|---|
| 0분 | 현금 10만, 빚 30만, 첫 정산 이자 9,000 |
| ~2분 | 노동 150회 → 전단지 일 시작(급여 1,500) |
| ~5분 | 오소리 빚을 줄이면 이자가 눈에 띄게 준다. 독사 골목이 열릴 수도 있다 |
| 10~17분 | 성실하게 누르면 빚 청산(성실 10분, 보통 17분) |
| 그 뒤 | 오두막(50만) → 창고(200만)는 노동+거래, 별장(1,000만)부터는 거래 없이는 사실상 불가능 |
| 언제든 | 200배 전액을 무작정 누르면 파산까지 중앙값 33초 |

### 4.2 배치 (3×3, 최소 360pt 폭에서 한 칸 약 112×72pt)
```
┌───────────┬───────────┬───────────┐
│ 숲속중앙조합│ 황금저축   │ 광장 전광판│   ← 먼 줄 (제도권)
├───────────┼───────────┼───────────┤
│ 마을 기록관 │  내 집     │ 친구네 골목│   ← 가운데 줄 (생활)
├───────────┼───────────┼───────────┤
│ 오소리 대부 │  일터      │ 독사 골목  │   ← 가까운 줄 (바닥)

```
- 건물마다 머리 위 표시: 빚이 있으면 원금(줄임 표기, 예 "15만"), 연체 중이면 빨간 딱지 "연체 1/2".

- 주인공은 선택한 건물 앞에 선다(0.3초 이동). 귀여운 동작(통통 튐, 꼬리)은 주인공에게만.

## 5. 노동 (`data/jobs.json`)

- 노동은 **마을 탭의 일터에서만** 한다 [사용자 확정]. 거래 탭에는 노동 버튼이 없다.
- 일터 패널의 큰 버튼을 누를 때마다 `payPerTap` 도토리를 받는다. 초당 12회까지만 인정한다.
- 조건을 만족한 일 가운데 가장 높은 것이 자동으로 현재 일이 된다. 일이 바뀌면 속보 띠에 한 줄로 알린다.
- 급여(`wagePerSettlement`)는 정산 때 자동으로 들어온다. 방치·오프라인 수입이다.

| 순서 | 일 | 1회 수입 | 정산 급여 | 여는 조건 |
|---|---|---|---|---|
| 1 | 길바닥 도토리 줍기 | 60 | 0 | 처음부터 |
| 2 | 전단지 돌리기 | 90 | 1,500 | 이번 회차 노동 150회 |
| 3 | 편의점 야간 알바 | 130 | 4,000 | 노동 500회 |
| 4 | 물류센터 상하차 | 200 | 8,000 | 노동 1,200회 |
| 5 | 삼솔전자 협력사 계약직 | 400 | 20,000 | 오두막 이상(주소지가 있어야 채용) |
| 6 | 잣스닥 상장사 정규직 | 1,500 | 100,000 | 별장 이상 |

- **차압**: 오소리 대부가 연체 중(연속 연체 1 이상)이면 노동·급여 수입의 30%는 현금으로 오지 않고 오소리 원금에서 깎인다. 버튼 위에 "수입의 30% 차압 중"을 표시한다.

## 6. 대출 사다리와 원금 탕감 도장 (`data/loans.json`, `data/friends.json`)

### 6.1 금융 4곳
| 단계 | 채권처 | 담보 | 한도 | 1회 대출 | 정산 이자 | 도장 1회 | 연체 한도 | 특수 규칙 |
|---|---|---|---|---|---|---|---|---|
| 1 | 숲속중앙조합 (1금융) | 집 필요 | 집 평가액의 80% (LTV) | 10만 | 1% | 5만 | 3회 연속 | 집이 없으면 거절(거절 횟수 기록) |
| 2 | 황금저축·캐피탈 (2금융) | 없음 | 집 단계별 60만 / 100만 / 300만 / 1,000만 / 3,000만 | 5만 | 2% | 1만 | 3회 연속 | - |
| 3 | 오소리 대부 (사채 1) | 없음 | 50만 / 100만 / 200만 / 500만 / 1,000만 | 10만 | 4% | 1만 | 2회 연속 | 연체 중 수입 30% 차압 |
| 4 | 뒷골목 독사 대부 (사채 2) | 없음 | 100만 / 200만 / 500만 / 1,000만 / 2,000만 | 20만 | 8% | 2만 | 2회 연속 | 선이자 40%, 연락처 제출 |

- **대출**: 원금 + 1회 대출액 ≤ 한도일 때만. 누르면 현금 += 대출액 × (1 − 선이자율), 원금 += 대출액.
- **독사 대부의 선이자** [사용자 확정]: 20만을 빌리면 12만만 받고 장부에는 20만이 적힌다.
- **연락처 제출** [사용자 확정]: 한 회차에서 독사 대부를 두 번째로 쓸 때부터 "지인 연락처 제출에 동의" 칸을 체크해야 빌릴 수 있다. 빌리는 순간 `contactsSeized = true`. 그 뒤 독사 대부가 연체되면 정산마다 모든 친구의 신뢰가 30씩 깎인다.
- **1금융 담보 규칙** [사용자 확정: 담보 없으면 거절]: 한도 = 0.8 × 현재 집 평가액. 부동산 하락 속보로 평가액이 내려가면 한도도 내려간다(이미 빌린 돈을 당장 회수하지는 않지만 추가 대출은 막힌다).
- **약관**: 각 채권처 패널에 "약관 보기" 한 줄이 있다. 누르면 그 자리에서 펼쳐진다(`terms`).

### 6.2 친구 5명 (이자 없음, 신뢰가 깎임)
| 친구 | 한도 | 1회 빌리기 | 도장 1회 | 절교하면 |
|---|---|---|---|---|
| 단짝 다람쥐 | 5만 | 2.5만 | 5천 | 빚을 탕감해 주고 절교 |
| 절친 너구리 | 10만 | 5만 | 1만 | 남은 빚을 독사 대부에게 넘김 |

### 6.3 원금 탕감 도장 [사용자 확정: 채권처별 도장]
- 각 채권처 패널에 그 채권처만의 도장 버튼과 남은 원금이 있다.

- 원금이 0이 되면 "완납" 도장이 크게 찍힌다. 과장된 연출은 이 순간과 파산 순간에만 쓴다.
- 도장은 정산을 기다리지 않고 즉시 원금을 줄이므로, 정산 직전에 찍으면 그 정산 이자가 준다.

### 8.2 시세 모델 [기획 결정: 시뮬레이션 시세만]
- 틱은 1초. 5개 종목 모두 어느 탭에 있든 계속 움직인다.
- `logP(t+1) = logP(t) + 추세 + σ·N(0,1) + 급등락 − k·(logP(t) − log(시작가))`
  - **추세**: 숨은 상태(상승/하락/횡보 = 35/35/30%). 매 틱 `switchProbPerTick` 확률로 다시 뽑는다(평균 약 150초). 상승이면 +0.15σ, 하락이면 −0.15σ.
  - **급등락(빔)**: `jump.probPerTick` 확률로 σ의 6~20배 크기, 방향 반반. 이런 틱은 `viaJump = true`.
  - **되돌림**: 시작가에서 너무 멀어지지 않게 약하게 당긴다.
- 난수는 시드가 있는 생성기(mulberry32)를 쓰고 시드를 저장한다. 테스트에서 같은 시드면 같은 시세가 나와야 한다.
- 차트는 최근 120틱 선 그래프. 장 마감 시간은 없다(24시간).

### 8.3 포지션
- 종목마다 포지션 1개(최대 5개 동시). 격리 마진: 잃을 수 있는 돈은 그 포지션의 증거금까지다. 현금이 음수가 되는 일은 없다.
- **입력** (한 화면, 팝업 없음 [사용자 확정]):
  - 방향: 롱(오른다) / 숏(내린다)
  - 배율: `1, 2, 5, 10, 25, 50, 100, 200`배 중 하나. `−` `+` 버튼으로 한 칸씩, 빠른 칩 `10 / 50 / 200`. 기본 10배.
  - 증거금: 현금의 `10 / 25 / 50 / 100`%. 기본 25%. 최소 1,000 도토리.
  - 손절: `없음 / −10 / −25 / −50 / −75`% (ROE 기준). 익절: `없음 / +25 / +50 / +100 / +200 / +500`%.

### 8.4 공식 (금액은 모두 정수 도토리. 수수료·펀딩비는 올림, 돌려받는 돈은 내림)
| 항목 | 공식 |
|---|---|
| 명목 금액 | `N = 증거금 × 배율` |
| 수수료 | 진입·정리 각각 `N × 0.0004` |
| 진입 | 현금 −= 증거금 + 진입 수수료 (현금이 모자라면 진입 불가) |
| 100% 선택 시 증거금 | `floor(현금 / (1 + 배율 × 0.0004))` — 수수료 몫을 남긴다 |
| 손익 | `PnL = 방향 × (현재가 − 진입가) / 진입가 × N` (롱 +1, 숏 −1) |
| 수익률 | `ROE% = PnL / 증거금 × 100` |
| 청산가(롱) | `진입가 × (1 − 증거금/N + 0.001)` |
| 청산가(숏) | `진입가 × (1 + 증거금/N − 0.001)` |
| 강제 청산 | 틱 가격이 청산가에 닿거나 넘으면 즉시. **증거금 전액 소멸**(돌려받는 돈 0) |
| 정리 | 현금 += `max(0, 증거금 + PnL − N × 0.0004)` |
| 손절가·익절가 | `진입가 × (1 + 방향 × ROE%/100 / 배율)` |
| 펀딩비 | 정산 때 포지션마다 `N × 0.0002`를 증거금에서 뺀다. 뺀 뒤 `증거금 + PnL ≤ N × 0.001`이면 청산 |

예: 도토코인 68,000에 200배 롱, 증거금 10,000 → N = 2,000,000, 수수료 800, 청산가 = 68,000 × 0.996 = 67,728(−0.4%). 가격이 +0.25% 오르면 ROE +50%.

- **손절·익절 체결**: 틱 가격이 지정 가격에 닿거나 넘으면 정리. 보통 틱은 지정 가격에, 급등락 틱은 실제 틱 가격에 체결한다(슬리피지). 같은 틱에 청산가도 넘었으면 청산이 우선이다(손절을 걸어도 빔 한 방에 청산될 수 있다).
- **추가 진입(물타기)**: 포지션이 있을 때 같은 방향으로만. 배율은 기존과 같아야 한다. 새 진입가 = `(N1 + N2) / (N1/진입가1 + N2/현재가)`, 증거금·N은 더하고, 손절·익절은 현재 설정을 새 진입가 기준으로 다시 계산한다. 반대 방향 버튼은 포지션이 있는 동안 꺼진다.
- 포지션이 열린 동안 손절·익절은 언제든 바꿀 수 있다. 배율·증거금 칩은 "추가 진입에 쓸 값"으로만 동작한다(배율 칩은 잠김).
- **마진콜 표시**: ROE가 −70% 아래로 내려가면 포지션 줄이 깜빡이고 `marginCalls` +1.

## 9. 정산 (`data/balance.json` `settlement`)

**주기 45초** [기획 결정: 시뮬레이션으로 결정, SIM_RESULTS.md]. 앱이 켜져 있는 동안 어느 탭에서든 흐른다. HUD에 남은 시간과 "이번 정산에 나갈 돈"이 항상 보인다. 10초 남으면 타이머가 강조된다.

정산 순서(한 틱 안에서 차례대로):
1. **급여** 지급(차압 반영).
2. **펀딩비**: 열린 포지션마다 부과. 부족하면 청산.
3. **납부**: `독사 → 오소리 → 캐피탈 → 은행 → 유지비` 순서로 현금에서 뺀다. 이자 = `round(원금 × 이자율 × 금리 속보 배수)`. 현금이 모자라면 낼 수 있는 만큼만 내고 나머지는 미납.
4. **연체 처리**: 미납이 있는 곳은 미납액을 원금에 더하고(유지비는 밀린 유지비로 쌓음) 연속 연체 +1. 다 낸 곳은 연속 연체 0.
5. **친구**: 갚기로 한 날이 지난 빚 → 신뢰 −20. 연락처 추심 → 모든 친구 신뢰 −30. 신뢰 0 이하 → 절교 처리.
6. **속보**: 진행 중인 효과의 남은 회차 −1, 새 속보 추첨(10장).
7. **파산 검사**(11장). 파산이면 엔딩 판정으로 넘어가고 아래는 하지 않는다.
8. 통계 갱신(정산 횟수 +1, 신용점수 등), 저장, 화면에 정산 결과 한 줄("정산: 급여 +1,500 / 이자 −9,000").

납부 순서를 무서운 곳부터로 한 이유: 연체 한도가 짧은 사채부터 막아 주어 플레이어가 억울하게 죽지 않게 한다 [기획 결정].

### 11.1 파산이 일어나는 세 가지 경우 [기획 결정]

### 11.2 엔딩 판정 엔진
파산이 확정되면 그 순간의 통계 스냅샷을 만들고 200개 엔딩의 `trigger`를 평가한다.

```
trigger = { type: "rule" | "proxy", causes: [원인…] | null, all: [[통계, 연산자, 값], …], note? }
```
- `causes`: 하나라도 파산 원인과 같아야 한다. `null`이면 원인 무관.
- `all`: 모두 참이어야 한다. 연산자 `== != >= <= > < has in`. 통계 값이 `null`이면 거짓.
- `rule` 114개: 카탈로그 조건을 게임 통계로 옮긴 것. `proxy` 86개: 게임에 없는 사건(미니게임, 특수 이벤트)이라 단순한 대용 조건으로 바꾼 것. 각 `note`에 무엇으로 대신했는지 적혀 있다.

**선택 순서** [사용자 확정: 미수집 우선 / 나머지 기획 결정]
1. 원인과 조건이 맞는 엔딩을 모두 모은다.
2. 아직 수집하지 않은 것이 있으면 그중 `priority`가 가장 큰 것(같으면 번호가 작은 것).
3. 전부 수집한 것뿐이면: 새 엔딩 없는 파산이 3번 이어졌을 때에 한해, 원인이 맞는 미수집 `proxy` 엔딩 중 번호가 가장 작은 것을 조건 무시하고 준다(도감 완성 보장 장치).
4. 그래도 없으면 수집한 후보 중 `priority`가 가장 큰 것을 다시 보여 준다("이미 수집" 표시).
5. 후보가 하나도 없으면 `END-001`.

**priority** = 분류 기본값(선물·청산 400 > 사채 300 > 친구 200 > 1금융·부동산 100, 기존 명세의 우선순위 그대로) + 조건 수 × 10 − proxy면 50 + 보정(END-200 +500).

원인마다 조건 없는 기본 엔딩이 하나씩 있어 후보가 비지 않는다: 유지비 END-039, 1금융 END-006, 2금융 END-018, 사채 1 END-041, 사채 2 END-097, 친구 END-101, 청산 END-158.

### 11.4 파산 연출과 재시작
- 화면 전체를 덮는 엔딩 화면: 정적 → 도장 소리와 함께 붉은 "파산" 도장 → 엔딩 번호·제목 → 그림(없으면 분류 색 바탕에 모티프 문장) → 대사 한 줄 → 그때의 상태(현금, 총부채, 버틴 정산, 마지막 배율) → "새 엔딩" 또는 "이미 수집(n번째)" → 도감 진척 `37 / 200`.
- 버튼 하나: **새 인생 시작**. 누르면 시작 상태로 초기화(현금 10만, 빚 30만, 텐트, 시세는 새 시드). 도감·누적 통계·기록은 유지.
- 엔딩 문구는 사실 그대로 한 줄. 피해자를 놀리지 않는다.

## 12. 도감 (마을 기록관)

- 전체 화면. 위에 진척 `n / 200`과 분류 칩 5개(전체 / 1금융·부동산 40 / 사채·추심 60 / 친구·관계 50 / 선물·청산 50).
- 200칸을 번호 순으로 모두 나열한다(세로 스크롤).
  - 미수집: `END-045 · ???` + 힌트(`hint`). proxy 엔딩은 힌트 앞에 "대용 조건" 표시.
  - 수집: 번호, 제목, 대사. 누르면 그 자리에서 펼쳐져 그림(또는 모티프 문장), 처음 얻은 날짜, 얻은 횟수, 그때의 상태가 보인다.
- 저장: `encyclopedia[END-xxx] = { firstAt, count, snapshot }`. 한 번 열린 칸은 닫히지 않는다.

## 13. 랭킹 (광장 전광판)

- **기준**: 한 회차의 최고 순자산(`peakNetWorth`). 순자산 = 현금 + 포지션 평가액 + 집 평가액 × 0.9 − 총부채.
- **MVP(로컬)**: 전광판에 마을 주민 9명(고정 순자산, `balance.json` `ranking.npcs`: 단짝 다람쥐 30만 … 독사 대부 30억)과 내 현재 회차, 내 최고 기록을 한 줄로 세운다. 내 순위가 실시간으로 오르내린다.
- **내 기록**: 끝난 회차 상위 20개(최고 순자산, 버틴 정산, 끝난 방식: 엔딩 번호 또는 은퇴).
- **은퇴**: 빚이 0일 때 전광판에서 "은퇴(기록 확정)"를 누르면 파산 없이 회차를 끝낸다. 엔딩은 주지 않는다.
- **나중(서버)**: 닉네임 + 최고 순자산 제출, 주간/전체 순위. 조작 방지를 위해 서버 검증이 필요하므로 MVP에서 뺐다.

## 14. 저장과 오프라인

### 14.1 저장
- 저장소: `localStorage` 키 `fof.save.v1` 하나(JSON). 저장 어댑터를 한 겹 두어 나중에 Capacitor Preferences로 바꿀 수 있게 한다.
- 구조: `{ version, savedAt, run: {…현재 회차 상태·통계·시세·난수 시드}, life: {…누적 통계}, encyclopedia, records, settings: { name, priceColors } }`
- 저장 시점: 정산마다, 대출·도장·이사·진입·정리·청산 직후, 앱이 가려질 때(`visibilitychange`).
- 불러오기 실패(깨진 JSON, 버전 불일치): 원본을 `fof.save.broken`에 옮기고 새 게임으로 시작. 안내 한 줄: "저장 데이터를 읽지 못해 새로 시작합니다."
- 도감과 누적 통계는 회차 초기화에도, "데이터 초기화"를 하기 전까지는 지워지지 않는다.

### 14.2 오프라인 진행 [기획 결정]
- 떠난 시간이 10초 미만이면 그냥 이어서 한다.
- 그 이상이면 **최대 정산 5회분(225초)** 까지만 따라잡는다. 5초 단위로 건너뛰며 시세·손절·익절·청산·정산을 그대로 처리한다.
- **연체로는 자는 사이 파산하지 않는다**: 어느 곳이든 연속 연체가 한도 − 1에 닿으면 시간은 거기서 멈춘다.
- **청산으로는 파산한다**: 포지션을 열어 둔 채 떠났고 청산되어 전 재산이 날아갔으면, 돌아왔을 때 엔딩이 기다린다(`offline = true`).
- 돌아오면 마을 탭 패널 위에 요약 한 번: "자리를 비운 사이 — 정산 3회, 급여 +4,500, 이자 −21,300, 도토코인 롱 익절 +12,400".

- 데이터 파일을 읽지 못함: "게임 데이터를 불러오지 못했습니다." + [다시 시도].
- 저장 실패(용량 초과 등): 속보 띠에 "저장하지 못했습니다. 저장 공간을 확인하세요." 게임은 계속.

## 16. 톤 규칙 (요약. 원문은 `docs/TONE_AND_MANNER.md`)

1. 캐릭터는 귀엽다 / 세계는 현실 그대로 / 결과는 현실처럼 가혹하다. 새 요소를 넣을 때 어느 층인지 먼저 정한다.
2. UI는 아주 간소하고 귀엽게. 현실감은 숫자와 문구로 낸다. 한 화면에 꼭 필요한 것만.
3. 금융 용어는 진짜로 쓴다(레버리지, 청산, 증거금, 선이자, 담보인정비율). 화폐 이름만 도토리.
4. 글은 사실 그대로, 짧게. 시스템 문구에는 감탄사·이모지를 쓰지 않는다. 주인공만 들뜬 반말.
5. 금지: 피·상처·신체 훼손·시신, 피해자 조롱, 실제 기업·은행·거래소 이름과 로고, 실존 인물, 엄마의 사고 직접 묘사, 투자 권유 문구, "볼주머니 = 현금 게이지" 아이디어(사용자 거절).
6. 귀여운 동작은 캐릭터에만. 과장된 효과는 완납 도장·청산·파산 순간에만.
7. 장소별 말투: 은행은 정중한 공문체, 캐피탈은 지나치게 친절한 영업 말투, 오소리는 투박한 반말, 독사는 낮고 정중한 존댓말, 친구는 반말(신뢰가 떨어질수록 짧아짐).

## 17. 접근성 기본

- 누르는 영역 44×44pt 이상, 서로 8pt 이상 떨어뜨린다.
- 글자 대비 4.5:1 이상, 큰 숫자·버튼 테두리 3:1 이상.
- 색만으로 뜻을 전하지 않는다: 상승·하락은 ▲▼와 +/−, 위험은 딱지 모양과 글자, 연체는 "연체 1/2" 글자.
- 흔들림·깜빡임은 기기의 "동작 줄이기" 설정(`prefers-reduced-motion`)이면 끈다.
- 숫자는 천 단위 쉼표. 100만 이상은 건물 머리표 등 좁은 곳에서만 "150만"처럼 줄인다. HUD와 패널은 전체 숫자.
- 본문 14pt 이상, 주요 숫자 20pt 이상. 기기 글자 크기 확대 시 패널이 넘치지 않게 최대 1.3배까지만 따른다.
- 화면 읽기 프로그램용으로 버튼에 이름을 단다(`aria-label`: "오소리 대부 원금 탕감 도장 1만 도토리").

## 18. MVP 범위

### 첫 빌드에 반드시 들어가는 것
1. 탭 두 개(마을, 거래)와 공통 HUD·속보 띠. 홈 화면 없음.
2. 시세 5종목 시뮬레이션(추세·급등락), 1초 틱, 선 차트.
3. 거래: 롱/숏, 배율 8단계, 증거금 4단계, 손절·익절, 추가 진입, 수수료, 펀딩비, 강제 청산, 종목당 1포지션.
4. 45초 정산: 급여, 이자, 납부 순서, 연체, 미납 이자 원금 가산.
5. 대출 사다리 4곳 + 친구 5명(선이자, 연락처 제출, 담보 규칙, 신뢰, 절교, 채권 양도).
6. 채권처별 원금 탕감 도장(배수 칩, 완납 연출).
7. 노동 클리커와 일자리 6단계, 차압.
8. 집 5단계와 이사, 유지비, 마을 속 집 외형·색감 변화.
9. 속보 9종.
10. 파산 3경로 + 엔딩 판정 엔진(200종 trigger 평가, 미수집 우선, 완성 보장 장치).
11. 엔딩 화면, 도감(200칸 전부, 힌트, 수집 기록 유지).
12. 전광판: 주민 9명과 내 순위, 내 기록 20개, 은퇴, 이름·색 설정, 초기화.
13. 저장(localStorage)과 오프라인 따라잡기(최대 5회, 연체 파산 보호).
14. 프롤로그 3장, 첫 거래 안내 줄.
15. 임시 그림: CSS 도형 + 기존 이미지(주인공은 `docs/art/chipmunk/C3_ribbon.png`를 `src/assets/`로 복사해 사용. 건물은 색 블록 + 이름).

### 나중으로 미루는 것
- 최종 그림(아래 목록), 소리·음악·진동, 캐릭터 표정 변화

## 19. 기술 구조 [기획 결정]

| 영역 | 선택 | 이유 |
|---|---|---|
| 틀 | Vite + React 18 + TypeScript | 화면이 패널·목록·버튼 위주. 가장 흔한 조합이라 코딩 에이전트가 한 번에 만들기 쉽다 |
| 상태 | Zustand 하나 + 순수 함수 엔진 | 게임 규칙은 화면과 분리한 순수 TypeScript(`src/engine/`). `(state, action) → state`. 화면 없이 테스트 가능 |
| 스타일 | 일반 CSS(CSS Modules) + CSS 변수 | 집 단계별 색감 5벌을 변수 교체로 처리. 설정이 필요한 도구를 줄임 |
| 차트 | 직접 그린 Canvas 2D 컴포넌트 | 120점 선 하나와 가로선 4개뿐이다. 가장자리 꼬리표, 귀여운 스킨을 마음대로 하기 쉽고 의존성이 없다. 캔들·지표가 필요해지면 그때 Lightweight Charts 검토 |
| 마을 | DOM + 이미지(절대 위치 3×3) + CSS 전환 | 건물 9개, 캐릭터 1명. 누르는 영역·글자·접근성을 그대로 쓸 수 있다 |
| 앱 포장 | Capacitor (iOS, Android) | [사용자 확정]. 저장은 어댑터로 감싸 Preferences로 교체 가능, 앱 가려짐·복귀는 `@capacitor/app` |
| 테스트 | Vitest | 20장의 수용 기준을 엔진 단위 테스트로 옮긴다 |
| 데이터 | `data/*.json`을 그대로 import | 숫자의 원본이 하나 |

**three.js를 쓰지 않는 이유** [사용자 요청: 검토]
- 그림체가 파스텔 소프트 셀 2D이고, 필요한 것은 그림 교체와 간단한 이동뿐이다. 3D 카메라·조명·모델이 필요한 장면이 없다.
- 화면의 대부분이 글자와 버튼이다. three.js를 넣어도 UI는 어차피 DOM으로 따로 만들어야 한다.
- 번들이 수백 KB 늘고, 앱 안 웹뷰에서 WebGL 컨텍스트 손실·발열·배터리 문제를 따로 다뤄야 한다.
- "삶이 나아지는 모습"은 집 외형 그림과 색감 교체로 충분히 보인다.
- 다시 검토할 때: 마을을 입체 디오라마로 돌려 보게 하고 싶어질 때. 그때도 마을 그림 영역만 캔버스로 바꾸면 되도록 마을은 컴포넌트 하나로 격리한다.

**폴더 구조**
```
data/                     숫자와 엔딩 (원본)
src/
  engine/                 순수 규칙. DOM·React 금지
    types.ts  rng.ts  market.ts  trading.ts  loans.ts  friends.ts  housing.ts
    labor.ts  events.ts  settlement.ts  stats.ts  bankruptcy.ts  endings.ts
    offline.ts  game.ts   (game.ts: 초기 상태, tick, 모든 action)
  store/                  Zustand 스토어, 저장 어댑터, 1초 틱 타이머
  ui/
    common/               HUD, 속보 띠, 탭 바, 버튼, 숫자 표기
    village/              마을 그림, 패널 7종
    trade/                차트, 주문 패널
    overlays/             엔딩, 기록관, 전광판, 프롤로그
  assets/                 임시 그림
tests/engine/             수용 기준 테스트
scripts/sim/              경제 시뮬레이션
scripts/data/             endings.json 생성기
```

**틱과 시간**
- 스토어가 1초마다 `tick`을 보낸다. 브라우저가 타이머를 늦추면 실제 지난 시간만큼 여러 틱을 한꺼번에 처리한다(최대 10초분, 그 이상은 오프라인 규칙).
- 정산 타이머는 틱 수로 센다(45틱). 벽시계가 아니다.
- 화면 갱신은 틱에 묶지 않는다. 노동 버튼 반응은 즉시.

## 20. 수용 기준 (Given / When / Then)

엔진 테스트로 옮길 수 있게 썼다. 숫자는 `data/` 기본값 기준.

### 시작·시간
- **AC-01** Given 저장 데이터가 없다 / When 게임을 시작한다 / Then 현금 100,000, 2금융 원금 150,000, 사채 1단계 원금 150,000, 집은 텐트, 일은 도토리 줍기, 순자산 −200,000이다.
- **AC-02** Given 게임이 켜져 있다 / When 45틱이 지난다 / Then 정산이 정확히 1번 실행되고 타이머가 45로 돌아간다.
- **AC-03** Given 같은 난수 시드 / When 시세를 100틱 만든다 / Then 두 번 실행한 결과가 똑같다.

### 노동
- **AC-04** Given 일터에 있고 일이 도토리 줍기다 / When 노동 버튼을 1번 누른다 / Then 현금 +60, `laborTaps` +1.
- **AC-05** Given 같은 1초 안에 / When 20번 누른다 / Then 12번만 인정된다.
- **AC-06** Given `laborTaps`가 149다 / When 1번 더 누른다 / Then 일이 전단지 돌리기로 바뀌고 다음부터 1회 +90이다.
- **AC-07** Given 일이 전단지 돌리기다 / When 정산한다 / Then 급여 1,500이 이자 납부 전에 들어온다.
- **AC-08** Given 오소리 대부 연속 연체가 1이다 / When 노동으로 100을 번다 / Then 현금 +70, 오소리 원금 −30, `garnished` +30.
- **AC-09** Given 거래 탭이 열려 있다 / Then 화면에 노동 버튼·도장 버튼·대출 버튼이 없다.

### 대출·도장
- **AC-10** Given 텐트에 산다 / When 1금융 대출을 누른다 / Then 돈은 들어오지 않고 `bankRefusals` +1, 거절 문구가 보인다.
- **AC-11** Given 오두막(평가액 500,000)이 있고 1금융 원금이 400,000이다 / When 대출을 누른다 / Then 거절된다(한도 400,000).
- **AC-12** Given 2금융 원금 150,000(한도 600,000) / When 대출을 누른다 / Then 현금 +50,000, 원금 200,000, `borrowCapital` +1.
- **AC-13** Given 독사 골목이 열려 있다 / When 처음 대출한다 / Then 현금 +120,000, 원금 +200,000, `upfrontPaid` +80,000.
- **AC-14** Given 이번 회차에 독사 대부를 1번 썼다 / When 동의 칸을 체크하지 않고 대출을 누른다 / Then 대출되지 않는다. When 체크하고 누른다 / Then 대출되고 `contactsSeized`가 true가 된다.
- **AC-15** Given 연체 0, 총부채 499,999 이하, 채권 양도 없음 / Then 독사 골목은 잠겨 있다. When 어느 곳이든 연체가 1번 생긴다 / Then 열리고 그 회차 동안 다시 잠기지 않는다.
- **AC-16** Given 현금 25,000, 오소리 원금 150,000, 배수 ×1 / When 도장을 누른다 / Then 현금 15,000, 원금 140,000, `stamps` +1.
- **AC-17** Given 현금 5,000, 도장액 10,000 / Then 도장 버튼이 꺼져 있고 "현금 부족"이 보인다.
- **AC-18** Given 원금 7,000, 도장액 10,000, 현금 50,000 / When 도장을 누른다 / Then 7,000만 빠지고 원금 0, "완납" 연출이 나온다.
- **AC-19** Given 배수가 "전액", 현금 80,000, 원금 150,000 / When 도장을 누른다 / Then 현금 0, 원금 70,000.
- **AC-20** Given 주인공이 일터에 있다 / Then 대출·도장 버튼은 보이지 않는다. When 캐피탈 건물을 누른다 / Then 주인공이 그 앞으로 가고 패널이 캐피탈 내용으로 바뀐다.

### 친구
- **AC-21** Given 너구리 신뢰 100, 잔액 0 / When 빌린다 / Then 현금 +50,000, 잔액 50,000, 신뢰 80.
- **AC-22** Given 신뢰 39 / When 빌리기를 누른다 / Then 거절, `friendRefusals` +1.
- **AC-23** Given 빌린 뒤 정산이 5번 지났고 잔액이 남아 있다 / When 6번째 정산 / Then 신뢰 −20, `odFriends` +1.
- **AC-24** Given 너구리 신뢰가 0 이하가 된다(잔액 50,000) / Then 절교, 독사 대부 원금 +50,000, `claimsSold` +50,000, 독사 골목 열림, 너구리 집은 닫힘.
- **AC-25** Given 단짝 다람쥐 신뢰가 0 이하가 된다(잔액 25,000) / Then 절교, 잔액은 0으로 지워지고 독사 대부 원금은 변하지 않는다.
- **AC-26** Given `contactsSeized`가 true이고 독사 대부 연속 연체가 1 이상 / When 정산 / Then 절교하지 않은 모든 친구의 신뢰 −30.
- **AC-27** Given 절교 3명 / When 다음 정산 / Then 원인 `friends`로 파산한다.

### 집
- **AC-28** Given 텐트, 현금 500,000 / When 오두막으로 이사 / Then 현금 0, 집 단계 1, `lastMoveDir` up, 마을의 집 외형이 바뀐다.
- **AC-29** Given 오두막 보유, 현금 1,600,000 / When 창고로 이사 / Then 드는 돈은 2,000,000 − 450,000 = 1,550,000.
